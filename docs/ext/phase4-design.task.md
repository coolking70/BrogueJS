## 目标

一个大型敌人以 N×N 格（先 2×2，再推广 3×3；4×4 只留扩展点）占据地图，具备完整的占位、移动、寻路、视野/感知、目标与攻击、渲染/UI、存档录像，以及能容纳它的生成场地。

## 设计稿必须回答的问题

1. **现状审计**：引擎里"某格上的生物"有哪些表示与查询（如 `HAS_MONSTER`/`HAS_PLAYER` 类格标志、按坐标查生物、生物 x/y 直接比较、邻接判断、交换位置、击退/拉拽、传送、召唤落点、掉落/坠落、地形与气体对生物的作用、物品拾取、门、陷阱触发）。列出调用点数量级与分类，标出哪些必须改为"占位表/footprint 查询"。
2. **底座能力 vs 模块内容的切分**：
   - 底座提供：footprint 组件/字段、占位表、按体型的可通行/寻路/距离图（含缓存策略与失效）、邻接/距离/视线以 footprint 为准的查询、渲染所需的只读投影。**没有任何多格生物时，模拟、状态、RNG 调用与现在完全一致**（可用测试证明，不要求 CE 逐字节，只要求未使用该能力的组合不受影响）。
   - 模块（建议 module ID 自拟，如 `giants`）提供：大型敌人定义、Boss 场地模板与生成接入、Boss 血条等 UI 贡献、必要的专属 AI 行为。只硬依赖底座；删除模块目录后底座多格能力仍可编译、测试（可用底座测试 fixture 覆盖）。
3. **规则语义**（每条给出明确决定和理由）：
   - 位置锚点（左上/中心）与 footprint 表示；移动时整体可通行判定；转向/挤过窄道；与其他生物交换位置、推挤；被击退/拉拽/传送/召唤/变形（polymorph 到不同体型）/坠落到下层时的落点搜索；生成落点。
   - 各格地形效果如何作用：火、熔岩、深水、陷阱、气体浓度、裂隙——任一格触发还是按主格/多数？只结算一次还是每格一次？
   - 攻击与被攻击：近战邻接以任一 footprint 格为准；穿刺/横扫/长矛/鞭/闪电/爆炸/范围技能（含 growth 的技能）对同一大型生物只命中一次；投掷物与弹道命中。
   - 视野与感知：被看见/看见他人的规则、潜行/噪声距离、隐身。
   - 玩家始终 1×1；盟友/俘虏/魅惑的大型生物是否允许（可先禁止，写明扩展点）。
4. **寻路与性能**：按体型膨胀的距离图如何计算、缓存与失效（与现有 `invalidatePathing` 等机制关系），2×2/3×3 在常规地图尺寸下的成本估计；不得让无大型生物的局多付成本。
5. **渲染与 UI**：刻符主题下多格字形的呈现方案（拼图字形/放大字形/轮廓），侧边栏条目、Boss 血条、目标高亮、录像回放显示；移动端 320/390 宽度可读性。
6. **生成**：Boss 场地模板（最小净空、通道宽度、入口），与现有生成的接入点；大型敌人是否限制在场地内；对未启用模块的地图生成零影响（启用时若改生成，说明 drift 基线处理）。
7. **持久化与录像**：footprint 与模块状态的存档位置、版本号、manifest；读档重建占位表；旧档政策（沿用"不迁移、版本不符拒绝"）。
8. **与阶段 3 的接口约定**（两模块互不依赖，只走可选软接口）：
   - 底座暴露只读 footprint 查询（给定生物 → 占据格集合），阶段 3 的攻击预警格按"攻击者 footprint + 相对攻击形状"计算，即可自然支持大型敌人。
   - 写明本阶段**期望阶段 3 遵守/可选使用**的接口，以及本阶段不会去做的事（如不实现预警、体力、韧性）。
9. **共享文件触碰清单**（重点，用于与 dot 的阶段 3 设计对照冲突）：逐项列出会修改的共享文件（如 `Game.ts`、`TimeCoordinator`、怪物 AI、`CombatSystem`、移动/寻路、FOV、渲染、`src/ext/world.ts`、`runtime.ts`、存档/录像），每项写改动性质（新增接口/改调用点/重构）与规模估计。
10. **分步实施计划**：建议形如 4a0 底座占位表重构（1×1 行为不变）→ 4a 移动与寻路 → 4b 攻击/目标/视野 → 4c 渲染与 UI → 4d 模块内容与 Boss 场地生成 → 4e 收尾与独立性验收；每步的验收标准、测试（含真实 Game 新局/存读/录像/seek 冒烟）、门禁档位（按 README 当前门禁政策）、需浏览器人工验证的项目。
11. **待维护者决定的问题**：列成编号选项（每题给推荐项与理由），不要自行拍板需要产品判断的事项。
