## 1 结论、模块边界与独立性

### 1.1 推荐边界

| 归属 | 内容 | 不承担 |
| --- | --- | --- |
| **foundation（新步 5A4）** | 可食世界物品类别与吃/扔/喂的受控效果执行；物品火接触统一钩子（地面、投掷落点、背包）；非魔法“未知种类知识登记表”与名称解析；不碰原生两条随机流的整局派生抽样；资源节点分组放置与地形偏好；生物需求时钟组件框架；生物离队（非死亡退役）；可被伤害唤醒的“沉眠”失能状态 | 蘑菇种类/数值/文案、同伴饥饿数值、营地经济 |
| **`foraging` 模块（5G1–5G2）** | 12 种蘑菇定义、生/烤/焦炭物品、12 种菌丛节点、外观名池与已知名、烤制政策、效果意图表、同伴饥饿数值与离队政策、`feed` 命令、自有 UI/locale/测试/配置手册 | 修改 Game/共用 codec/时间；营地、居民、厨师；crafting 配方 |
| **`settlement`（5C1/5D）** | 起始储粮、粮仓、居民日粮、短缺与离开、厨师加工、农田/猎人；按标签软接受 foraging 蘑菇 | 读取蘑菇种类、揭示知识、导入 foraging 数据 |
| **`crafting`（5B）** | 不再有菌节点、菌材料、口粮物品与烤口粮配方 | 任何食物制作 |

模块 ID `foraging`，目录 `src/ext/modules/foraging/`，只硬依赖底座（含 5A1/5A2/5A2-S/5A3/5A4 能力），不 import 任何其他模块。`defaultEnabled:false`。

### 1.2 独立性与组合

- **未启用 foraging**：不安装任何定义/组件/需求时钟/知识组；同伴不饿、无喂食命令、无菌丛；不调用新增随机抽样；经典与其他组合的机械状态、RNG 与录像不受影响（5A4 的底座能力在无声明者时走零成本快速路径，§12.3）。
- **仅 foraging**：完整闭环——下层发现菌丛→采集→吃/喂→学会种类→用火烤→同伴饥饿与喂食。不需要营地、crafting 或任何其他模块。
- **foraging + settlement**：唯一联动是**标签软接口**：foraging 的可食物品带公开标签 `food.ingredient.mushroom`；settlement 厨师只按标签计数，不读种类、不改知识；同伴饥饿排除已登记的营地居民（读 settlement 可选查询 `settlement.resident-status.v1`，缺席则全部盟友都按同伴规则）。任一方缺席时另一方照常工作（§10.4）。
- **foraging + combat/giants/growth/narrative**：无必需联动。giants 群体只把核心视为一个同伴（成员不各自吃饭）；combat 篝火虽不是火地形，但维护者明确要求篝火也能烤：首版即通过 §6.1 第 5 条的软接口支持（§16 Q12 已定为 B）。
- **可移除性**：删除 `src/ext/modules/foraging/` 后，剩余树须通过 boundary、vue-tsc、build、剩余 `test:ext` 和剩余子集 smoke；5A4 的底座 fixture（`fgfixture`）留在底座测试里，不依赖 foraging。

- 好 5 种（回复、通心、暗影、力量、加速），坏 6 种（中毒、幻觉、混乱、呕吐、沉眠、麻痹），中性 1 种（爆裂）。坏种饱腹略高，形成“饿了冒险吃”的诱惑。
- 种类数按深度：D1–2 五种，D3 七种，D4 八种，D5 九种，D6–7 十一种，D8+ 十二种。
- 状态时长与原生药水关系：心灵感应/幻觉为药水 1/2–1/3，暗影 1/2，加速 2/5；所有状态沿原生 `applyTimedStatus`/`setStatusDuration` 的“取较大值”语义，不叠加。
- “暗影”按已批准方向中的 darkness-vision 解读为复用原生 `darkness`（黑暗药水的隐匿/视野变暗效果）。若维护者原意是“黑暗中视物”的新能力，则需新状态，见 §16 Q3。
- 状态免疫沿原生：例如已免疫中毒/麻痹的目标不受影响；此时视为“无明显效果”，不揭示。
- 数值上限：力量来源走 5A2-S `native.strength` 物化键（L4 临时、`grantPolicy` 不 refill），到期按“降则钳制”回落；不产生永久成长或 XP。

## 4 菌丛节点与生成

### 4.1 节点

每种蘑菇一个节点定义 `foraging.node.<kind>`（共 12），`kind:'fungus'`（C5-1 已有），无工具、徒手采：

| 字段 | 值 |
| --- | --- |
| `capacity` | 3 |
| `harvestTicks / unitsPerHarvest` | 100 / 1 |
| `yield` | 该种类的生蘑菇 ×1 |
| `regeneration` | periodic 1 / 32000 tick（= 1 营地日，§10.2） |
| 显示名 | 由知识登记表解析：未知时“{外观名}丛”，已知时“{已知名}丛”（§5.5） |
| 字形/颜色 | `菌` / 统一 `#B8A4E0`（**所有种类相同**，不能用颜色区分种类） |

采集走 5A2 的 `harvest` 世界工作（同 crafting：可见/距离/容量/空间预检、100 tick、可打断、退款）。节点耗尽后按再生恢复；再生在未管理层也照常（节点自有时点，C5-1 §5.4）。

### 4.2 每层分组抽取与地形偏好（需 5A4 能力，§9.4）

| 项 | 提案 |
| --- | --- |
| 每层菌丛数 | D1–3：1–2；D4+：2–3（均匀抽取） |
| 种类选择 | 每个菌丛独立按 §3 权重在“最浅层 ≤ 当前深度”的种类中抽取；同层可重复 |
| 每局上限 | 120（40 层 × 3）；与 crafting 剩余 144 合计 264 ≤ 512；每层 crafting 8 + foraging ≤3 = 11 ≤ 32 |
| 偏好 | 候选格按“与发光菌/菌林地形 ≤3 格”“洞穴型区域”加权（偏好 4：1），无偏好候选时退回普通合法格；不覆盖楼梯/机关/巨兽侧室/其他 interactable |
| 无位 | `skip` 并写收据，不重生成楼层 |
| 随机来源 | 整局派生抽样（§9.3），**不推进原生实质/装饰两条流**；同种子有无 foraging 的地形、怪物、原生物品逐项相同（实体 ID 数值允许不同） |

### 4.3 天然产量估算（供 §10 对照）

每层平均约 2.5 个菌丛 × 每日回 1 个 ≈ **每层每日 2.5 个蘑菇 ≈ 0.5 份口粮**（厨师 5:1），低于 1 名居民每日 1 份。玩家首次路过每层平均可采 ≈ 2.5×3 = 7.5 个，期望饱腹约 1900，且含坏种风险；同伴进食会分走一部分。该供给约等于每层一份口粮的量级，与原生食物保底叠加，属有意放宽，审阅时可下调（Q1）。

## 5 外观、命名与知识

### 5.1 命名规则（已批准，强制）

1. 外观名、外观描述、已知名、风味文本、节点名和消息**不得描述或令人联想任何真实蘑菇**：不用真实物种名或俗名，不写菌盖、菌褶、菌柄、菌环、菌托、斑点、伞形、颜色花纹等写实形态，也不用“X色+菇/蘑”的组合。
2. 一律用明显虚构的奇幻特征：异常的光、声、温度、符文、晶体、烟雾、星光、倒影、时间感等。统一后缀“菌”，不用“菇”“蘑”“蕈”；玩家可见的统称（UI、消息、营地库存、厨师界面）一律用“菌”或“菌类”，“蘑菇”只是本设计文档的工作用语。
3. 描述不得暗示药理或毒理（不写“有毒”“可治病”“致幻”等），避免玩家把游戏知识带回现实，也避免用现实知识判断游戏内种类。已知名可以概括游戏内效果（如“愈合菌”），因为它是游戏规则名，不是现实物种。
4. 名称只能来自 §5.2/§5.3 的**审阅名单**；运行期不得拼接、截取或生成新名称。增删名单须改数据、过 T-NAME 测试并由维护者审阅。

### 5.3 已知名与风味文本

### 5.4 知识状态与学会途径

知识按**定义**记录（生与烤是不同定义，分开记）：

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `unknown` | 只知外观 | 初始 |
| `tasted` | “吃过/喂过，没看出效果” | 吃下或喂下后未满足 §3 的揭示条件（如满血吃回复、处于免疫、爆燃菌、烤后被去除特性的种类） |
| `known` | 知道种类（烤定义另知道“烤后保留/去除”） | 玩家自己吃下且满足揭示条件；或可见同伴吃下且其反应可见（§7.5）；或目睹该种生菌爆炸 |

- `tasted` 不是鉴定：它只记录事实，不推断“无效果”。烤定义处于 `tasted` 时 UI 显示“吃过，无明显效果”，不显示“烤后无效”，因为满血吃烤愈合菌也会这样。
- 生定义 `known` 后，其烤定义名称显示为“烤{已知名}”，但烤后是否保留特性仍是独立知识：未知时附注“烤后效果未知”。烤定义被揭示时同时得知“烤后保留”；若烤后特性被去除，玩家只能通过其他途径（例如生定义已知、烤定义多次只得 `tasted`）自行推断，引擎不替玩家下结论。
- **任何原生知识来源都不覆盖**：鉴定卷轴不列出也不能选中可食世界物品；探测魔法不给极性标记；`tryIdentifyLastItemKind` 不包含该组；药水/卷轴/魔杖等任何“揭示全部”效果都不触及；同伴、营地厨师、商店（无）均不揭示。
- 绰号：沿原生 `call` 体验，玩家可给 `unknown/tasted` 定义起绰号，存于知识登记表；知道后绰号不再显示但保留。
- 揭示是同一次吃/喂/爆炸事务内的写入，消息形如“这是愈合菌！”。

### 5.5 名称解析与 UI 命名

| 对象 | 未知 | `tasted` | 已知 |
| --- | --- | --- | --- |
| 生蘑菇 | `3 个低语菌` | `3 个低语菌（吃过，无明显效果）` | `3 个愈合菌` |
| 烤蘑菇 | `烤低语菌` | `烤低语菌（吃过，无明显效果）` | `烤愈合菌`；生已知但烤未知时 `烤愈合菌（烤后效果未知）` |
| 焦炭 | — | — | `焦炭`（始终已知） |

## 6 烤制、焦炭与爆裂

### 6.1 “火接触”事件（5A4 统一钩子，§9.2）

以下任一情形对一件可食物品（整堆）产生**一次**火接触：

1. 火地形（`T_IS_FIRE`）生成到物品所在格（原生 fillSpawnMap 的 burnItems 路径）；
2. 物品被扔、掉落、坠落或漂流进入正在燃烧的格；
3. 每客观块的地面燃烧检查（`burnFloorItems`）发现物品位于燃烧格，**且该物品不在火接触冷却期内**；
4. 玩家着火瞬间的背包判定（§6.4）；
5. **篝火/灶台烘烤**（维护者要求，首版即实现）：玩家站在 combat 篝火或 settlement/crafting 带 `station.hearth` 标签的灶台/火炉相邻时，可对背包中一堆可食物品执行“烤制”（记录命令，100 tick），或把物品扔进篝火/灶台所在格，均视为一次火接触。foraging 通过可选只读端口识别“可烘烤的火源交互对象”（由提供方声明 `heatSource` 标签），未安装 combat/settlement/crafting 时该入口不出现；交互对象本身不被引燃、不产生火地形。

地面物品在一次火接触后进入 **10 回合（1000 tick）冷却**，期间同格持续燃烧不再触发；捡起或放入容器时清除冷却。这样短暂的火只烤一次，持续 10 回合以上的火或重新点燃才会把烤菌变焦炭。熔岩（`T_LAVA_INSTA_DEATH`）沿原生直接毁掉可食物品（爆燃菌改为爆炸）。深水、坠落、偷取等沿 MATERIAL 原生规则。箱、托管、残骸中的物品首版不受火接触（C5-1 容器本身的火损另有规则）。

### 6.2 变形规则

| 当前 | 火接触结果 |
| --- | --- |
| 生（非爆燃） | 整堆变为同种“烤”定义，数量不变；饱腹 +100 |
| 烤 | 整堆变为焦炭（饱腹 20，无效果） |
| 焦炭 | 烧尽，删除，播 `DF_ITEM_FIRE`（同卷轴） |
| 生爆燃菌 | 爆炸（§6.3），整堆删除；不存在“烤爆燃菌” |

烤制政策：每局对 11 个可烤种类各自派生抽样决定 `keep`（烤后特性不变，好坏都保留）或 `strip`（烤后只剩饱腹），各 50%，独立（§9.3）。政策是规则状态，不显示给玩家；推荐不存档，由种子与规则指纹派生，读档重新计算并在会话缓存（§12.1）。

可见格内变形写消息（“低语菌被烤熟了。”“烤低语菌烧成了焦炭。”“焦炭烧尽了。”），名称按知识解析，不泄露种类或烤制政策。

### 6.3 爆裂

- 吃下或扔出（不入火）：无任何效果，吃下只得 150 饱腹并记 `tasted`。
- 任何火接触：在物品所在格（背包内则在玩家位置）以整堆为单位爆炸一次：数量 1–2 用 `DF_EXPLOSION_FIRE`，≥3 用 `DF_BLOAT_EXPLOSION`；伤害、点火、连锁全部沿原生 GAS_EXPLOSION 地形结算，不另造伤害公式。
- 爆炸若在玩家可见范围内（或在玩家背包内），该生定义变为 `known`，消息“爆燃菌炸开了！”。
- 连锁：爆炸点燃邻格其他可食物品，按 §6.1 各自产生火接触（可能连环爆）；每次爆炸是独立 DF 调用，顺序按物品稳定 ID。

### 6.4 背包着火规则（引擎事实与新提案）

事实：CE 与本引擎都**没有**“玩家着火时背包卷轴燃烧”的机制（只烧地面卷轴，且是确定的，没有概率）。因此已批准方向 #5 中“同卷轴燃烧概率”无可沿用的现成规则。提案：

- 触发点只在玩家燃烧时长 **0→正** 的着火瞬间（`exposeCreatureToFire` 播“你着火了！”的同一点）；持续燃烧期间的刷新不再判定。
- 按背包字母序，对每一堆可食物品独立以 **1/3** 概率产生一次火接触（生→烤、烤→焦炭、焦炭→烧尽、爆燃→爆炸）。
- 用实质 RNG，在固定位置、固定顺序抽取；背包里没有可食物品时**不抽**，故不启用/不携带时 RNG 不受影响。
- 同伴与怪物携带的物品不判定（原生无对应规则）。

此为本设计自定，需要维护者确认（§16 Q2）；备选：(B) 燃烧期间每客观块每堆 10%；(C) 着火必然全部接触。

## 7 同伴饥饿与喂食

### 7.1 谁是同伴

启用 foraging 时，满足以下全部条件的生物带 `foraging:companion-need` 组件：玩家的盟友（`isAlly`，跟随链指向玩家）；非 `MONST_INANIMATE`；非限时召唤（存在 `lifespan_remaining`）；giants 群体只给核心；不是营地已登记居民（`settlement.resident-status.v1` 可选查询，缺席则不排除）；不在 foraging 数据表 `nonEaters`（按怪物模板 ID，首版提出候选名单待审，§16 Q10）。组件在成为同伴的同一事务中创建，失去资格（叛离、被支配解除、登记为居民）时移除，不残留。

### 7.2 数值

| 项 | 提案 |
| --- | --- |
| 饱腹上限 / 加入时 | 2150 / 1800 |
| 消耗 | 每 200 tick −1（玩家的一半；1800 约够 3600 回合） |
| 饿（≤300） | 仅提示，无惩罚 |
| 虚弱（1…150） | 命中 −20%、伤害 −25%（5A2-S 查询键临时来源，`native.accuracy` increased −2000bp，伤害 more −2500bp） |
| 饥荒（0） | 命中 −40%、伤害 −50%；开始离队计时 |
| 离队 | 连续处于 0 达 30000 tick（300 回合）后离队（§7.4） |
| 回升 | 任何进食使饱腹 >0 即清除离队计时；惩罚随档位即时变化 |
| 不掉血 | 同伴不会饿死，也不因饥饿扣 HP |

惩罚是 foraging 的 statSources 纯函数（读需求时钟当前值），不写原生 `weaknessAmount`，与原生虚弱状态互不干扰。数值进入 foraging 规则指纹。

### 7.3 时间与离层

需求值用 5A4 的**懒物化需求时钟**（§9.6）：存 `value / lastSettledTick / zeroSinceTick`，读取时按 `simulationTicks` 差值整数计算，不每回合写状态。留在其他层的同伴照样随世界时钟消耗；回到该层时在入层事务里一次物化，若已满足离队条件则在入层时离队（消息“{{name}} 在你离开时离队了。”）。档位变化与离队截止由底座在客观块按 actor ID 顺序检查，只比较整数，不抽随机。

### 7.4 离队（不死亡）

到期时：

- 同伴在玩家视野外：立即经底座“离队退役”（§9.6）移出整局，携带物品落在原地，不发死亡事实/XP/死亡 DF；日志“{{name}} 饿得受不了，离开了队伍。”
- 在视野内：先转为“离队中”：解除跟随与盟友身份但不敌对（底座提供非敌对离开态），向最近楼梯或视野外移动，至多 20 回合后无论位置均退役。期间喂食无效（已决定离开）。
- growth/narrative 可选地收到“离队”事实（非死亡）；不触发复活/掉落表。

（呈现方式为提案，§16 Q4。）

### 7.5 喂食命令 `foraging.feed`

- 外层：`executeCommand('ext:command', JSON.stringify({module:'foraging', action:'feed', payload}))`。
- payload `{v:1, targetId, targetRevision, itemId, inventoryStamp}`；`targetId` 是被喂对象的公开实体 ID，不是行动者。
- 资格：目标可见、Chebyshev 距离 1 且有交互线、是同伴（§7.1）、存活、未麻痹/沉眠；物品在玩家背包，是可食世界物品或原生 FOOD（口粮/芒果）。不满足 → 0 tick/0 物/0 RNG 拒绝。
- 若喂后会超过上限的部分 >0，沿原生“不太饿”确认；答 No 记录、零成本。
- 成功：耗玩家 100 tick；物品减 1；目标饱腹增加（原生 FOOD 按其 nutrition，口粮 1800），然后执行同一效果意图（§9.1）作用于目标。
- 同伴效果与反应（可见时写消息；“揭示”= 该定义变 `known`）：

| 特性 | 同伴效果 | 反应可见、可揭示 |
| --- | --- | --- |
| 回复 | 回复 30% maxHp | 仅当喂前受伤 |
| 中毒/混乱/麻痹/沉眠/加速 | 对应原生状态，时长同玩家 | 是 |
| 呕吐 | `nauseous` 15 + 饱腹 −300（不低于 150） | 是 |
| 临时力量 | 伤害 more +25%，400 回合（同伴无力量属性） | 是 |
| 心灵感应 / 幻觉 / 暗影 | 上同名状态（对怪物无明显机械意义） | **否**：只记 `tasted`，需玩家自己吃才能学会 |
| 爆裂 | 无 | 否 |

- 同伴 AI 永不自己进食，也不拾取蘑菇；喂食永远被接受（拒绝会泄露种类）。

## 10 营地食物经济（对 settlement 的要求）

本节给出数值与规则提案，正文写入[阶段 5 设计 §8.3a](phase5-settlement-world.md#83a-营地食物经济2026-10-06-批准方向)与 5C1/5D 行，实施归 settlement。

### 10.1 时间单位

**营地日 = 32 经济周期 = 32000 tick（约 320 回合）**，与一张补给工作单的最长寿命（32 周期，P5-D03=A）对齐：一张单恰好覆盖一天生产。日边界 = `floor(simulationTicks / 32000)` 变化；在场与离线用同一经济核，分段一致性照旧。（若取 100 周期为一日，则一单只覆盖 1/3 天，离场营地几乎必然净亏，见 §16 Q1。）

### 10.2 消耗、储粮与短缺

| 项 | 提案 |
| --- | --- |
| 口粮单位 | 1 件原生 FOOD（口粮或芒果）= 1 份 |
| 日粮 | 每名居民每日 1 份，在日边界按居民 actor ID 顺序从营地粮仓扣除真实 Item |
| 粮仓 | 营地标记自带的补给堆容器 + 玩家指定为“粮仓”的箱；只有粮仓里的 FOOD 计入 |
| 起始储粮（5C1） | 建立营地须从背包存入 **2 份**口粮单位到补给堆；这 2 份为锁定储备：营地存在期间玩家不能取出，居民优先吃它；撤销营地时退还剩余 |
| 短缺 | 当日缺粮的居民短缺 +1（最多 3），吃上则 −1 |
| 效率 | 0 档 100%；1 档 50%；2、3 档生产停（只自救/守卫） |
| 离开 | 处于 3 档后再缺粮一日 → 离开营地（H7 退役；离线则在结算提交中退役并写收据），**不死亡** |

### 10.3 厨师与食材

- 只有分配为“炊事”的居民能加工；需要一个带 `station.hearth` 标签的工位（settlement 自有灶台，或已装 crafting 时其火炉经标签匹配）。
- 每批产出 1 件原生 `ration_of_food`（已知、去除全部特性），workTicks 500，`offlineEligible:true`，放入粮仓。
- 每份口粮只用**一类**食材，不混用；最终单位数：**蘑菇 5、作物 3、猎物肉 2**（保持草案）。蘑菇按标签 `food.ingredient.mushroom` 计数，生、烤、任意种类（含爆燃菌）都算 1；焦炭不算食材。类别优先级默认“蘑菇→作物→肉”，营地可调整；同类内按 Item ID 升序消耗。
- 厨师从不揭示种类：不改知识登记表、不显示种类名以外的信息；爆燃菌在加工中不爆炸（加工不是火接触）。
- 理由：蘑菇平均生饱腹约 260，5 个 ≈ 1300 → 1800，加工有约 40% 增益且去除风险；作物/肉为 settlement 自有材料，作物 3、肉 2 让农田和狩猎成为主力。

### 10.4 产量对照（刻意低于消耗）

| 来源 | 每日产量（提案，5D 数值任务最终审批） | 折合口粮/日 |
| --- | --- | ---: |
| 天然菌丛（营地层） | 约 2.5 个（§4.3） | 0.5 |
| 农田 | 1 名农夫最多照看 6 格，每格每日 1 作物 | 2 / 农夫 |
| 猎人 | 1 名猎人每日 2 份猎物肉（需营地层有登记猎场） | 1 / 猎人 |

例：4 人营地（2 农夫、1 厨师、1 猎人）每日消耗 4，产出 4 + 1 + 0.5 = 5.5 → 净盈余；只靠天然菌时任何 ≥1 人营地都净亏。离场时一张补给单最多一日生产，之后只消耗，长离场营地会逐步断粮——这是 P5-D03 有界离线的直接结果。

### 10.5 软接口

- foraging 缺席：厨师只用作物/肉；粮仓与日粮不变。
- settlement 缺席：foraging 无营地相关行为；同伴饥饿照常。
- 两者都在：按标签互认；同伴饥饿排除已登记居民；居民被护送离开营地时仍由营地日粮负责（不加 foraging 组件）。

## 12 存档、录像与确定性

### 12.1 输入与随机

- 改状态输入只有：原生吃命令、原生扔命令、`ext:command` 的 `harvest`（5A2）与 `foraging.feed`、确认答案。火接触、爆炸、需求截止都发生在引擎时间推进中，属于命令的确定后果。
- 随机：外观分配、烤制政策、节点数量/种类/候选全部用 H4 派生抽样（不推进原生两流）；背包着火判定用实质流（仅在有可食物品时抽）；显示与名称解析 0 RNG。
- 外观分配与烤制政策不存档：由 `runSeed + 规则指纹` 派生；规则或名单变化即指纹变化，旧档按严格版本拒绝。

### 12.2 存读校验

读档在退休旧局前校验：可食定义存在且属已启用 owner；知识行引用合法定义、状态枚举、绰号长度；需求组件只在合格同伴上且 `lastSettledTick ≤ simulationTicks`；离开态截止合法；冷却字段只在地面物品上。不修补错档。

### 12.3 零影响

未启用 foraging：5A4 各能力无声明者时不建根、不挂组件、不检查截止、不抽随机；地面燃烧检查只在存在可食物品时走新分支。测试用同种子“底座 5A4 前/后、无 foraging”对比 UR2/UR3/UR4、drift 与录像体积。

### 12.4 版本

5A4 一次分配 foundation 号 +1（新包键、知识根、需求组件、冷却字段、slumber 状态；whole-run 仅在实体字段合同变化时随外壳升，预期因冷却字段与 slumber 而升）。foraging `1.0.0`、state schema 1、payload v1、`worldSdk:1`。5D1 修订 C5-1 离线 DTO：`OfflineRules` 增 `dayEpochs:32`、日粮按日边界；`OfflineResidentState` 增 `unfedDays` 与 `departed`；新增 `OfflineEffect` `resident-departure`；随 settlement/foundation 版本升号，不迁移旧档。
