# 阶段 4 设计修订任务书（r2）：通用多格与复合体敌人

> 分支 `ext/phase4`，在已提交的初稿 `docs/ext/phase4-giants.md` 基础上修订。本轮仍**只改设计文档，不改代码/测试/数据，不 commit**。

## 维护者的新要求（2026-10-05）

1. **P4-D07 = A**：Boss 不因身份获得额外免疫，可被变形、复制等。此外还要考虑**大型敌人主动发起的**形态变化、分裂、复制、召唤自身副本等能力（例如阶段转换时换形态/换体型、一分为二、复制出另一只）。
2. **占位形状不限于正方形或长方形**：未来要支持任意形状（如 L 形、十字、长条、不规则多格），初稿只用 `size: 1|2|3` 表示方形不够。
3. **复合体与部位**：要支持“由多个部位组成、作为整体行动、但各部位有自己的行动轨迹与独立攻击/受击判定”的敌人。极端例：巨型蜘蛛、章鱼——身体整体移动，每条腿/触手各自移动、各自攻击、各自被击中；玩家可以**部位破坏**，破坏后影响整体（移动变慢、失去某种攻击、暴露弱点、失衡等）。九头蛇（多头各自攻击）、长蛇（主体 + 身体段）也属于这一类。

这些不要求在第一批实施中全部做完，但**底座的数据模型与迁移必须一次性按通用模型设计**，不能先按“N×N 单实体”迁移数十个占位入口，以后再为复合体重迁一遍。

## 修订方向（Claude 的建议，请审计代码后确认或提出更好的方案，理由写清）

把能力拆成两个正交原语，方形 N×N 只是特例：

1. **刚体足迹（rigid footprint）**：一个实体占据一组相对格（任意连通格掩码，数据定义），可选朝向（4 向旋转/镜像）。整体原子移动；旋转需要扫掠/中间状态检查。按“形状 × 朝向”建可通行图与距离图。可选**命中区（hit zone）**：足迹内的格标注部位标签，部位有独立 HP/护甲/弱点倍率，可被破坏——这是“不独立移动的部位”的轻量方案（如石像的核心格）。
2. **复合体（body group / composite）**：多个成员实体（各自有刚体足迹，通常 1×1 或小形状）组成一个群体，共享一个“大脑”。成员与核心之间有约束（最大距离/牵引范围/连接拓扑），成员可各自移动、各自攻击、各自受击、各自带状态。群体级规则包括：伤害是否/按多少比例传给核心、部位破坏事件对核心属性的影响（数据驱动的修正表）、核心死亡时成员如何处理、全部腿被毁后核心如何处理、经验与击杀事实只结算一次等。

请在设计中明确回答：

- **数据模型**：形状掩码、朝向、命中区、群体/成员/约束/部位修正表的 schema 草图；初稿的 `CreatureSpatialComponent{size}` 如何改为通用形式；方形如何作为特例无额外成本。
- **占位索引**：格 → (实体, 命中区) 的映射；查询与去重的键是“实体”“部位”还是“群体”，按效果类别由谁决定（例如横扫同时扫到同一只蜘蛛的两条腿：各算一次还是按群体只算一次？给出推荐与可配置点）。
- **调度与行动**：推荐由核心一个调度项驱动、成员动作作为群体回合内的子动作，还是成员各自调度？考虑确定性、录像、与阶段 3“多回合攻击/预警”的衔接，给出推荐与理由。成员（腿）的移动规划：落脚点选择、受阻时对核心移动的影响、确定性与性能上限。
- **状态归属**：哪些状态是群体级（如精神类：魅惑、纷争、恐惧、麻痹?）、哪些是成员级（燃烧、中毒、缠绕?）；用数据分类而非硬编码。
- **部位破坏**：破坏条件、对整体的影响（速度、可用攻击、平衡/硬直、暴露弱点、移动方式变化）、破坏后成员是移除、变残骸地形还是保留为不可行动体；可再生/再生长是否支持（扩展点）。
- **主动与被动形态变化**：变形（含体型/形状/成员数变化，单实体 ↔ 复合体）、分裂、复制、召唤、阶段转换。保留哪个 ID、多出的成员如何生成与预留落点、少掉的成员如何移除（不能当作“被击杀”触发死亡效果/经验），全部原子提交或整体无效。被玩家变形（如把老鼠变成巨蛛、把巨蛛变成老鼠）同样走这一套。
- **寻路与性能**：任意形状 × 朝向的可通行/距离图成本；旋转在窄道中的规则；复合体成员的约束求解成本；给出成员数/形状格数/朝向数的上限建议。
- **渲染与 UI**：任意形状身体、复合体（核心 + 腿/触手）的刻符呈现；部位可选中、部位血量/破坏状态在 Boss 血条或检视面板中的展示；手机窄屏可读性。
- **与阶段 3 的接口**：预警格以“发起攻击的成员足迹 + 相对形状”计算（腿砸、触手横扫）；部位破坏与阶段 3 韧性/硬直的可选联动（软接口，缺席时的替代行为）。
- **与阶段 5 的潜在复用**：阶段 5 设想用多格单位表示部队；复合体/群体模型能否作为部队编队的基础，写成扩展点即可，不要设计阶段 5。

## 分步计划要求

重新给出分步方案，原则：
- 第一步（底座迁移）就按通用模型建立占位索引、形状掩码、去重键、群体标识，但内容和规则只开放最简单的情况（例如：单实体 + 方形，以及测试 fixture 的任意形状），保证一次迁移不返工。
- 之后的推荐顺序大致为：方形大型敌人纵切（可玩闭环）→ 任意刚体形状与朝向 → 命中区与部位破坏 → 复合体（成员独立移动/攻击/受击）→ 主动形态变化/分裂/复制 → 收尾。每步可独立验收、可在任意一步停下而已交付部分仍完整可用（维护者希望保留取舍空间）。
- 每步写明验收标准、测试、门禁档位（按 README 当前政策）、浏览器人工验证项。
