### E1 用户补充：被围营地的离线暂停（必须实现）

营地存在未结束的已物化在场袭击时标记为“被围”。玩家离层、入侵者冻结期间，**仅该营地的全部离线生产与离线摘要结算暂停**，直到玩家返回并通过真实事件终结条件结束袭击后恢复；离层逃避袭击不能换取离线产出。仅返回、读档、开菜单、换岗位、取消订单不解除被围。

- 暂停包括离线劳动 / 产出 / 交付、需求扣粮 / 欠额 / 离营等离线经济摘要，以及该营袭击损失摘要；不能只禁新订单而让旧订单、在途票据或已排摘要继续兑现。现场原生战斗与在场需求仍走既有规则，其他未被围营地正常结算，不冻结全局世界时间。
- 持久化被围依据和暂停边界；冻结实体与事件身份不变。结束袭击只恢复结束之后的合格时间，**不追补暂停区间的生产、需求或损失摘要**。保存、加载、回放、seek、分段长离场与多次往返都必须保持这个排除区间，不能“解围后补产”。
- 已有材料 escrow、容量预留、已完成但待入库产物保持真实归属，不吞料、不复制、不提前入库；恢复后只按原交付合同兑现已合法完成的产物。未完成订单保留已赚进度和剩余合格工作预算，暂停不增加批数、不刷新日配额或自动续工；绝对日期变化不能转换成额外可结算周期。
- 被围状态与事件结束、离线排除水位须在同一可信提交中更新，失败整体回滚。UI 显示“被围 / 离线结算暂停”及原因，不提前声称已恢复；玩家死亡继续冻结整局。

## 2 已批准约束与本步范围

- 新局 settlement 袭击选项默认关闭，只在开局确定；规则配置纳入 manifest 身份，整局固定。关袭击仅停止额外事件，原生怪物、火与毒的既有危害保留。关 settlement 时不得残留袭击 UI、计时器或实体。
- 每营最多 1 个未结事件，全局最多 4 个在场 / 待展开事件；无人空营不生成追杀波次。沿用 8 营、同地牢层 1 营、每营 16 人 / 全局 64 人、当前层 128 活动实体 / 512 空间格上限，不能另设绕过预算的袭击池。
- 5E1 首批只生成普通原生单格袭击者，复用现有怪物 AI、盟友规则和战斗调度。大型袭击属于另批 5E2；不引入战争系统、远征、自动营地扩张或工作属性奖励。
- 离场静态结算不跑隐藏战斗，不杀居民、不毁营；只盗基础材料 / 口粮，单次最多可盗库存 25%，唯一装备 / 护符不盗。设施耐久不得被摘要降到最大耐久 25% 以下；已有更低耐久不凭空修复。
- 在场仍可能真实死亡 / 结构毁坏，走既有死亡、结构损伤和物品事实。玩家死亡冻结整局，不补结未处理离场窗口。
- 5C2（营地选址 / 可选地表 site）、5D3（叙事招募）均非依赖，继续后置，是否纳入 5Z 前范围待定，见 [5Z 登记](phase5z-remainders.md)。dot / giants2 由 Claude 中转，本地不派发、不等待其回执。

## 4 触发、缩放与有限事件（可逆参数按下列推荐实施）

本节数值是本步可调默认值，尚非旧设计批准的数值；集中登记在 settlement 自有规则中，并计入规则指纹。禁止用墙钟、UI 浏览次数、load / seek、远程查看推动压力或抽样。

- 压力按实际世界模拟时间每 1000 tick 更新；建营后首 32000 tick 为宽限，已结事件冷却 32000 tick。只有启用袭击、归属有效、至少一名存活留营居民、玩家未死亡才积累。护送中居民不计留营人口；长期断粮离营按 5D 先更新资格，无人后停止新事件。
- 每周期增压 `1 + ceil(P/4) + D + N`：P 为当时合格留营人口；D 为 `min(3, floor((depth-1)/5))`，合法深度至少 1；N 为上一已完成周期真实完成的生产批数，上限 4。取消、材料预存、查看和未完成订单无噪声。阈值为 `64 + 8*(lastEventOrdinal % 3)`，上次序号持久化；触发后预警 2000 tick。
- 同营已有事件时只在该事件预算内合并压力，严重度封顶，不排新队列。全局 4 槽已满时保留营地有界压力和延期原因，按稳定营地 ID 公平轮转准入；每次真实时间边界最多尝试一次，查看不得重试。已生成事件绝不靠压力不断增援。
- 首批人数预算 `min(8, 1 + ceil(P/4) + min(2, floor(F/2)) + min(1,D) + S)`：F 为营内完好且有真实生产用途的设施数，最高只计 4 个；装饰、箱子和重复摆拆不计噪声。触发时固定 P/F/D、规则指纹及基础人数预算；S 为预警 / 延期中合并的严重度加成，每额外 64 点压力加 1、上限 2，物化或摘要前最终锁定，之后不追加敌人；人口、已付生产能力越高营地越显眼，但不再全局乘营地数。新生普通阵容使用原生、与深度相称的有限白名单，不含召唤链、分裂增殖或大型 body；选择来自派生随机流，不污染原生战斗 RNG。
- 预警只通过真实已知信息发出“营地有威胁 / 延期 / 袭击开始”等，不凭空揭示隐蔽坐标或完整阵容。远营仅显示最后报告时间与当时消息，返回汇总才更新现场事实。
- 到期在当前层物化须先检查整批落点、原生可达入口、完整占位 / 实体预算与所有权。只用合法已知营外边缘 / 入口，不生成在屋内、岩石、owned region 冲突处，不造地形或重生成层。无法完整落地则保留同 eventId 延期和原因，下个有效时间边界重试，不半批提交、不无限搜索。
- 事件至少区分 warning / deferred / active / aftermath / closed，状态转移和 ordinal 在唯一持久根里。完整生命周期必须列成实现表；重入、反复切层、加载和重复日志不能生成新 ID、重算 loss 或刷防御 XP。历史压缩为有界收据和单调水位，不让事件数组随长局无限增长。

## 5 守卫、结构与灾后修缮

守卫仍由玩家经 5D 公开命令分配合法岗位，遵守口粮、休息、危险打断和盟友规则。真实敌情优先于生产与回岗；沿原生感知、防御 / 寻路攻击，不全图读敌人、不跨层追击、不瞬移、不平白增加全营命中或伤害。战后按原规则返回岗位；不能因为警报强行恢复疲劳或饱食。无 combat / giants 的 settlement 单模块闭环必须成立。

攻击与火灾伤结构走 5A3 的可信损伤事务及抗性。只有已有可信动作语义允许攻击的结构才成为原生攻击对象；不让所有怪物隔墙自动拆房。设施毁坏沿已有清理路径撤销岗位、取消失效订单、退还未耗材料和释放预留；真实死亡统一注销岗位 / 床位、归属人口并保留真实物品。可选 growth / narrative 只消费既有可信事实，不因摘要或事件关闭补发击杀、生产或防御奖励。

灾后维修交付可公开触发的玩家修缮命令：预览目标 / 修复量 / 材料 / 耗时，确认后经同一所有权、距离、revision / CAS 和付费事务。建议仅恢复未毁坏组件；已毁坏按原建造规则重建。维修耗材按原建造配方乘本次修复耐久比例逐项向上取整，非零修复至少付实际材料；耗时按同一比例折算、最低 100 tick。复用原有施工中断 / 退料机制，失败不吞料、不免费加血，不新造居民自动维修订单。维修无需等待袭击关闭，也不能修复别人的组件。

离场防御使用活着、有粮且岗合法的守卫、完好门墙、真实已付资源；本步不另建战备税 / 弹药经济，未登记已付资源的加成为 0。不计床、装饰、损坏空壳，也不把修缮预留料当可盗库。

## 6 离场口径与经济守恒（已批准 A/A/A + 被围暂停）

1. 已物化 active 事件随原生层冻结，保存原实体、动作 / HP 和 eventId；不同时跑该事件的静态损失。返回继续原战斗，不能复制单位；占用的槽不因玩家离层释放。被围营地在此期间全部离线生产和摘要按§1暂停，结束后不得追补。以下静态结算条款仅适用于未被围的合格营地。
2. 尚未物化的事件到期时仅做一次静态计划。防御快照取相同绝对周期的合法守卫和已知设施，不运行隐藏 AI、寻路、火毒传播或真实 RNG。离场口粮资格来自 5D 正常需求支付 / 欠额，袭击不额外吃一遍。
3. 推荐确定性防御计分：每合格守卫 2 点，每个完好墙 / 门 1 点且屏障贡献封顶 8；攻击点为触发时人数预算。`q = max(0, attack-defense)/max(1,attack)`。可盗每种基础材料 / 口粮的总量损失不超过 `floor(eligibleQuantity*q/4)`，再按稳定 stack ID 和派生流分摊；不按每个小栈先取整导致分箱套利。物资很少时可为零损失，不向上取整突破 25%。
4. 设施同事件总损伤预算建议不超过合格组件总 maxHp 的 `q/4`，稳定组件 ID 派生分配；逐件最多减到 `ceil(maxHp/4)`，已低于此值不再受摘要损伤。实际 hp 损伤还需服从可信结构抗性 / 事务，不能用原始 hp 写口规避 5A3。不生成物品掉落或强行拆除。
5. 同周期沿用 5D 已有“需求优先、产物下周期才可用”的经济顺序；袭击插在需求资格确定后、当期新生产扣料前。只能盗当时已入库且无预留 / escrow 的物资，不能同时在库存、票据、订单、在途产物上扣第二次。与 5D 实际顺序若不吻合，原作者先列窄合同差异给维护者核对，不暗改需求和交付时序。
6. plan 仅值对象；commit 一次提交 loss、组件耐久、停工原因、事件收据及水位。任一 provider / writer / 版本检查失败整体回滚，不先推进事件水位。重试同 eventId 用同派生种子；保存 / 读取 / seek 必须恢复完全相同结果，不能把事件已结但扣库未结写入档。
7. 连续离场最多一次摘要；之后保留“待回营查看”的有界状态和严重度，不继续追补长尾波次。实际回到该营 region 后一次汇总损失、欠粮、停工与维修需求并重新武装，下一事件仍受冷却限制。摘要完成后释放全局在场 / 待展开槽，营地自身仍由 aftermath 禁止重开；摘要不生成残敌、XP、虚构死亡或掉落，已有原生敌人不因此消失。
8. 绝对时间及稳定 ordinal 定位边界，跳过无事件长尾使用有界计算，不能逐 tick / 逐日追跑数年。分段离场与一次长离场在相同输入事实下结果一致。5D 的每单 32 周期是生产上限，不能被误用成时间冻结或无限生产；袭击无权自动续工。

## 7 存档、录像、UI 与软联动验收

- 唯一持久事件根归世界状态，模块配置和规则身份只保存必要值；严检 enum、数量、上限、ID 唯一、owner / level / camp、event→actor 引用、阶段与水位关系，拒绝 NaN / 超界 / 重复预算 / 伪造已结票据。新 Game、原活局 load、录像回放、关键 seek 与续录共用同规则重建，袭击开关不得取载入时的菜单偏好。
