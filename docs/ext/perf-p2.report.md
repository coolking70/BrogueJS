## 实施边界

1. 内部不可变 JSON 必须先分离、校验并深冻结，凭证保存在 WeakSet；规范化结果由 WeakMap 持有。只读上下文可以共用这些结果，可写上下文继续获得独立副本。外部浅冻结、accessor、循环、非有限值不能借 revision 或 Object.freeze 绕过准入。growth 的无变化观察不再提交整态；持久事实真正变化仍校验并发布。
2. 属性来源的组件读取记录包含模块、被读角色和组件名，保留缺失读取与跨角色读取。组件写入只清除实际读者；整态/原生变更仍走保守失效。来源依赖表设上限，溢出退回全局失效。growth 在不可变配置下按有效属性、作用域、上下文和 L0 值缓存派生行；校验预算、来源排序、BigInt 和舍入不改。属性准入同批共享 DAG 求值。
3. JSON savepoint 仍保存完整逻辑状态，只复制可写容器；深冻结分支在嵌套层之间共享。每个 savepoint 保有自己的可写副本，失败不能回到外层错误时点。原生战斗、身体、跨层、营地的既有完整写集继续保留，不因性能删掉可能受效果影响的对象。

### 64居民峰值评估

R1先做同worker诊断：在原64居民用例的每次`settleResidentNeeds`前后记录performance区间、进程CPU用时和堆占用，由同一worker的PerformanceObserver记录GC。两轮不开CPU采样，峰值26.897/25.209ms，提交中GC为1.479–2.430ms；第三轮仅对8次提交分别开100μs V8 CPU采样，峰值29.022ms。诊断临时注入原测试后原字节恢复，未改计时断言、输入、预热次数、50ms门限或强制GC；诊断数据不充作正式wall配对。
