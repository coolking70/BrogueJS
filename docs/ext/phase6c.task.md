## 2 目标、范围与非目标

**目标**：让套装组合、白装镶嵌、符文之语及工位改造成为当前刷宝循环的真实功能，并把新来源接入统一的可信事件、事务、知识、属性及录像链。以框架可扩展、功能正确和性能预算通过为验收标准。

既定方向不再询问：数值平衡整体后置；loot 默认推荐 growth，仍允许显式单开；未来有职业/流派，当前沿公开属性键与贡献目录扩展。新目录需要可用的初始参数与有限内容，**配置冻结不等于调参验收**：不得用“平衡延期”交付空目录/空成功命令，也不得为达到旧强度代理擅改掉率、怪物曲线或 cap。

允许触达：`src/ext/modules/loot/**`、其 i18n/测试/目录；C3 所需 crafting 配方与公开适配；C4 可信来源的最小宿主接点；真实缺口涉及的 item/world/stats/codec/通用 UI 接口及合同、测试登记。每项共享补口须先列当前缺口、权限、写集、失败行为和版本差量。模块不得私引其它模块或持有活 Item/Game 写引用。

非目标：CE 对照、旧开发档迁移/兼容、扩背包或装备槽、怪物穿玩家装备、商店/交易/跨局仓库、世界地图或新 site 生成系统、职业内容大扩充、T7、唯一品批量扩充、主题/美术、Worker/WASM及全面性能工程。不为普通 C 子步运行完整 npm/ext/drift、组合穷举或单删/单留。发布须另获授权。

### 3.2 必须保持的通用约束

- `Item.moduleData.loot` 是装备实例唯一真相；模块 state 不复制物品图。符文材料复用 C5 MATERIAL、stack≤99、容器/escrow/退款，不增加物品类别。所有权覆盖背包、装备、地面、已访问层、箱子、工作托管及退款根，不能双占、丢失或重复发放。
- 所有玩家状态输入经 `game.executeCommand` / `executeItemCommand`；UI 只收已知 DTO，确认/取消和工作入口沿已有录像边界。请求使用稳定 ID、严格字段、revision/CAS；拒绝陈旧、跨 owner、跨局、重复和越权输入。
- 保留每件≤6随机词缀/≤8固定行/≤4孔，owner≤4KiB、总moduleData≤8KiB、深度≤16、loot state≤4KiB；沿现行属性行/provider/总预算。目录上限建议沿设计：32套、每套≤4件、64符文之语、33符文。物品接纳遵守现行 C5/C6 根预算，不把原生历史自然增长误改成8192硬读档限。
- 准入时校验目录、引用、预算与有限整数；运行时只读用冻结索引，按已装备最多4件和每件最多4孔求值。不逐帧/回合扫描全物品根，不每次查询重新验证整目录，不在查询里开事务、揭示、抽实质随机或发布状态。
- 新来源遵守每事件/每件随机预算及分桶；原有 floor/kill/encounter/vault 资格与顺序不借机重写。部分接纳、无容量和正常不接管不是异常；异常须恢复完整世界写集、引用身份、双流、ID、收据、消息、物化值及缓存，不能只回滚模块 state。
- 套装/符文/符文之语作为 L2 来源，经已有管线和物化账本生效；资源升容不补、降容钳制。knownOnly 比较包含“换掉一件导致整个套装阈值变化”，但不得泄露未知成员或未知奖励。鉴定仅失效知识；机械写入、卸装、否定、GC、回滚、load/seek分别保持P2失效语义。
- 无 growth/combat/crafting/settlement/giants 时按真实公开能力 fallback/omit 或关闭相应动作，不按包名猜能力，不生成死引用。未来职业/流派通过注册标签、属性键、目录表达，不硬编码职业名或职业专属装备槽。

## 4 分步交付与停点

### 4.1 6C1：套装闭环

交付：套装定义与不同 pieceId、固定行、2/3/4件阈值；套装自然掉落与接纳收据；真实装备/卸装生效、详情/比较/过滤/来源显示、鉴定/分解及强化接线。建议首批2套各4件、只用已有属性节点，兼顾不同玩法取向；不把未来职业限定写进首批。

- 按**当前装备的不同 pieceId**计数，同件双戒不重复计，两个不同戒指件可以计两件；多个已达阈值建议累计生效。set/piece定义及阈值稳定排序，不受目录/import/装备遍历顺序影响。
- 建议套装件沿设计采用每局每种件唯一、仅实际接纳记收据；与普通 unique 收据分别标识，拒绝错误位图/非法件身份。库存、地面、容器不贡献装备件数；无候选的降级策略在C0冻结，不能无限重抽。
- 未鉴定套装保持机械作用，但隐藏件名/套名/未知奖励；已知比较按已知成员保守计数。完整鉴定与首次实际生效揭示的归属在C0列明，查询不得代替触发。套装固定行复用现有知识与强化路径，cap=4。
- 新增set掉落权重和分解基表是缺项，按C-D2提交最小配置；套装可分解、确认明确损失且不退收据。批量分解、未知目标和满背包规则不回退。

**停点**：自然生成→拾取→装备形成阈值→换装解除/恢复→鉴定/分解→当前版存读/回放/seek通过；双戒去重、2/3/4阈值、混套和失败回滚有独立期望。稀有完整套装可用合法受控场景补齐，但不能把手塞数据当自然链。限定门禁、UI清单与性能通过后交报告，停止于C1。

### 4.2 6C2：插槽、符文物品与符文之语

交付：白色武器/护甲按基底/ilvl表生成0–4孔（戒指0孔）；符文材料真实掉落、拾取/堆叠/箱内保存；`socket`、单符文效果、序列匹配转换、详情/比较和成本确认。建议首批4种符文、2条符文之语，覆盖武器/护甲；全部上限仍须通过受控边界测试。

- 嵌入命令 `{v:1,itemId,runeItemId,revision}`，成功消耗1枚符文、100 tick，按嵌入顺序追加。默认仅操作自己背包中未装备且不受锁定的合法目标，满孔/错误类别/材料不足/No/CAS失败0成本；没有免费撤销，取回必须走C3工位。
- 只有普通底材孔位恰好填满且基底类别/孔数/完整序列匹配，才在同一事务成为runeword；单符文修正**被替换**，不能与整词奖励叠加。不匹配保留单符文效果；匹配规则不得有歧义，非法目录在准入时拒绝。
- runeword 不进入掉落池，cap=0。白装可能已强化到10，与转换后cap冲突必须先定规则：推荐C2只允许未强化底材开始镶嵌，有镶嵌符文的底材禁止强化；不能删除已付强化或存出不合法物品。该限制属C-D3待裁定，不冒充原设计已有。
- 孔数/已嵌序列、材料名称、可见配方与词奖励的知识合同分开；推荐玩家主动嵌入的符文效果及匹配成词结果已知，底材原有未知信息不被一并揭示。材料不走装备词缀熟悉度。
- 增加材料掉落须复用受控接纳而非模块直接spawn；若当前DropItemSpec不能承载worldItem，在C2先补最小通用材料输出提案，沿原根预算、无落点与随机桶约束。不能等C4后才让符文可获取。
- 分解镶嵌物应警告符文损失；推荐不返还符文，set/runeword分解表显式定义。否定对镶嵌修正的影响、底材/词身份保持规则须在C0写表，不能套用6B4“原生runicType”开关来猜。

**停点**：符文真实获取→顺序嵌入→不匹配/匹配两路→生效/比较→保存/回放闭环；0/1/4孔、堆叠99/拆堆、双提交、非法重复组合、强度/知识无双加和容量失败通过。工位未上线时明确无拆卸按钮。限定门禁、三档UI与性能通过后交报告。

### 4.3 6C3：工位拆卸/重铸、craft来源和容器软联动

交付：可选 `station.forge` 工位，宿主 WorldWork 工作票据/托管/完成/中断退款；拆最后一枚或全部符文、重铸一条随机词缀；`loot.item-roll.v1` 受控 prepare/commit 协议及声明 `lootRoll:{maxRarity}` 的配方；箱内只读列表/过滤沿现有取回流程。

- crafting/loot仅软联动。仅loot时套装/镶嵌可玩、工位动作不可用；仅crafting时同配方按既有P5-D10输出 **+0已知**，不抽loot骰；双开且有合格工位/配方时才启用。合成最多魔法，不开放稀有/唯一/套装/符文之语直出。
- 装备输入的锁定、预留、托管、当前/跨层保存及退款是通用宿主权限；先补合法原生装备所有权支持，不把装备伪装worldItem。材料和目标进入票据后不可同时装备/分解/镶嵌/转箱；完成回到预留输出，失败走预留退款根。
- 拆卸返还数量/材料成本/工时在C0数据表冻结；建议保留取出的符文。拆卸runeword须同事务退回normal、去掉词奖励，按剩余序列重算单符文，保持底材ID。满背包有合法预留或拒绝，不能落空吞物。
- 重铸建议只允许已鉴定magic/rare的可重铸正面随机行，玩家选行；同位置/类别/互斥组约束内重选词缀、按当前ilvl合法阶掷值，保留其它行、基底/稀有度/强化/腐化负面。允许变差/同结果并事前提示，区别于6B4精炼取大；不重铸唯一/套装固定行或符文之语。更改原生符文族会涉及额外补丁权限，建议首批排除该族，见C-D4。
- prepare/预览/接单不掷结果；完成时在宿主受预算RNG及同一事务内消耗托管、roll、校验、接纳和记完成序号。异常不能转为普通+0输出，也不能已扣料后另开自由回调。craft产物以配方指定基底装配，不随机spawn再覆盖。
- 接收前拒绝0成本；**工作已开始后的时间与已完成批次不退**，只退未完成投入，取消/离层/工位销毁/死亡/provider失败沿C5合同。以票据及批完成序号防重复；保存、载入、重访、seek不能再次产出。

**停点**：真实造/用工位→接单→中断退款→重新接单完成→箱内取回→存读/回放；各缺席组合有因果用例而非全子集。预留失败、完成各写边界故障、provider缺席/抛错、重复票据和素材守恒通过。跨模块导入/测试依赖清楚，限定门禁、UI与性能通过后停止。

### 4.4 6C4：part/site 新来源

交付前先提交来源台账：**真实宿主触发点 → 可信事实 → 资格/幂等键 → roll → 接纳/收据 → 回滚 → 已知投影**。不能只扩字符串联合或注册空provider就声称来源可用。

- **part**：从部位破坏真实提交安全点发多消费者事实，不占用 `combat.part-break.v1` 单provider。建议每 `(groupId,partId,generation)` 恰一次；“generation”必须为宿主可信生命周期身份，不能由模块伪造。明确再生/换形/分裂是否开启新资格；盟友死者、行政拆除、克隆/召唤/无奖励主体排除，杀伤者沿既有非行政因果口径。普通kill、encounter与part可分别发生，但同一来源不重复发。读档/seek/离层/失格传播均有反例。
- **site**：无地下深度时使用 `siteIlvl=1` 初始配置，不伪造depth=1参加深度公式；origin需要明确地点类型/稳定实例及可选深度，严格校验非法混搭。来源是可信地点产出事件，不能每次打开箱子/重访/读取UI就掉落。site怪物倍率缺深度时推荐中性，不能借D1曲线补齐。
- C4-0核查是否已有真实可达site产出入口；若没有，**只交site协议/拒绝无入口的测试，并列“site玩法接线待前置世界任务”**，不得悄悄扩成世界生成/新地表地图。维护者可据此裁定phase6范围收口；不能无决定自行把未做项标完成。
- part/craft的既有物等加值分别+2/0沿numbers；part掉落概率、数量与表匹配须新增有限配置。新来源不能改变旧来源优先级或复用encounter收据冒充完成。用紧凑有界收据/宿主事实生命周期，不存无限事件历史。

**停点**：part真实破坏→接纳→跨层/读档不重发；site若有生产入口则真实进入→产出→重访不重发，否则按明确延期裁定交协议边界。缺giants/无body事实时part不可触发，缺site时无死按钮。限定门禁、相关UI与性能通过，交6C汇总，不自动发布。

起草核对的现状为foundation17/itemSdk2、loot module/rules0.5.0、pack0.2.0/schema1、实例v2/state1、growth1.10.0、crafting1.0.0；whole-run7/recording4/origin2，world5 schema4/worldSdk1/edibleSdk1。实施开工再次按实际代码核对，不能只信旧合同标题。

| 身份 | 建议分配原则 |
| --- | --- |
| loot module/rules | C1/C2/C3/C4独立交付建议0.6.0/0.7.0/0.8.0/0.9.0；如范围或批次变更重排，不预占最终1.0.0。玩法变化必须变规则身份 |
| pack/schema | C1新增sets建议pack0.3.0/schema2；后续新增runes/words/工位/来源按实际结构逐步升schema与pack。已有字段仅数值或启用变化不盲升schema，机械目录必须重算指纹 |
| 实例/state | 激活set/piece或增加词身份等持久结构，建议C1实例v3；后续序列/来源形状再变再升。套装收据若新增持久结构，state1→2；不能靠允许未知字段或load补默认兼容旧数据。派生件数/缓存不落盘 |
| foundation/itemSdk | 最小新公开权限/事件/持久协议实际变化时由集成人统一升下一号；C1若仅模块内变化不升。C2材料输出、C3工位装备托管及C4事实可能需升，分别列接口/写集/真实类型见证和hash，不自动连续占号 |
| worldSdk/world schema | C3确需扩WorldWork公开签名或托管格式才升（候选worldSdk2）；明确替代冻结合同，world持久结构变化才升schema，禁止改字节仍称SDK1不变。edible无关保持 |
| crafting/growth/其它模块 | crafting新配方字段/roll协议建议1.1.0并升相关schema；growth仅消费既有公开键则保持1.10.0，giants/settlement只有真实合同或规则变化才升 |
| whole-run/recording/origin | 容器形状保持则继续7/4/2，靠模块/foundation身份严格拒旧；真正容器变化再升，不为了每个功能盲升 |

分别登记源码、dist、静态pack、有效能力目录、配置/规则指纹、SDK、性能manifest；locale正文不入机械指纹，配置/能力fallback及可选内容筛选必须入身份。旧档拒绝不是缺包用例的替代，同版本完整链仍必须通过。

每步最终交任务对应报告、合同差量、三档复核结果/待验清单、唯一全删结果及性能证据身份。报告须清楚区分“实现完成”“限定门禁通过”“浏览器待验”“性能待验”“维护者接受的延期”和“可发布”；本文草案不提前宣称任一项通过。
