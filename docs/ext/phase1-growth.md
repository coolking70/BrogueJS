## 3. 经验来源、归属与反刷

### 3.1 奖励规则

- 击杀：仅“自然生成、最初是敌对、致死时仍敌对、非行政移除”的有奖励实体有 XP。每个 `rewardId` 最多一次。召唤物、幻影、分裂新体、周期刷怪、测试重置房复制体默认 0；变形继承原奖励 ID/额度，复活不刷新。特殊剧情敌人将来可显式定义唯一奖励。
- 定价：每种原怪物在 growth 内容表标一个固定 `threatRank r ∈ [1,20]`，`killXP = 6 + 2*r`（8–46）。1a0 默认数据包提供完整67种怪物样例报价表；1a按配置使用并校验真实目录覆盖；绝不按本次生成深度、当前 HP、玩家等级或强化后的自身等级动态报价。样例报价表不是强度标定结论；1a只验证数据及奖励语义，不修改原怪物目录，不做奖励分布测量或强度校准。
- 首访：成功进入从未访问过的 D2–D26，`20 + 5*depth` XP；D1 为 0，往返楼梯、读档、seek、坠层后重访不重复。跳过楼层不补发未访问奖励。全首访合计 2250 XP；26 层以下/返回地表暂不新增探索奖励。
- 物品：看见、拾取、堆叠、重拾、魔法探测不奖励，防刷也避免提前透露真名。首次**真正获知一个物品种类身份**奖励 10 XP，每局最多 300；药水颜色等外观不是种类 ID。已知种类的第二件完整鉴定、附魔数值揭示不再奖励。需新 `itemKnowledgeChanged` 事实事件，不能把现有 `itemPickedUp` 当鉴定。
- 剧情预留：`grantReward {recipientId,rewardKey,amount,reasonKey}` 是受信叙事模块通过底座发的已验证领域操作，不对玩家开放任意加经验命令；key 是定义 ID+剧情实例 ID，持久收据幂等，读档不重新发奖。阶段 1 没有实际剧情奖励。
- XP 不因饥饿/时间/反复搜索/承受伤害/制造物品自动增长；没有“每回合经验”。满级 XP 钳在满级阈值，避免无限整数增长；收据仍记录以免未来改上限后重复兑现。

### 3.2 谁获得击杀 XP

| 情形 | 推荐归属与接线 |
|---|---|
| 玩家近战 | 明确攻击者的效果来源；攻击未命中/全吸盾不生成虚假伤害贡献；有致死事件才结算 |
| 投掷武器 | `Game.throwItemAt`→`CombatSystem.resolveThrownWeapon` 独立传来源，不能依赖 `beforeAttack` |
| 玩家法杖/魔杖/法术 | 从法器提交或施法者传到 Bolt 反射/命中/效果，直接伤害和挂毒/燃烧分开存；UI 选目标时不写来源 |
| 盟友致死 | 有合法队伍归属时主角 `floor(XP*0.8)`，致死盟友拿剩余；不能每个盟友各拿完整份。玩家自己致死全给玩家；其它 NPC 独立队伍全给真实致死者 |
| 反射、反伤 | 反射者/反伤者成为 XP 责任者，原施法者仍留机械施法来源；新增反射事实记录真正反射者，不能把反击误记给仍在栈内的攻击者 |
| 毒/燃烧延迟致死 | 使用该状态保存的来源，施加者离层或死亡仍可辨认；施加时的队伍身份和结算时资格均校验，不能只查现存对象 |
| 击退入熔岩/坠落 | 只有显式位移效果与其紧接的落地致死能保留来源；普通追赶导致敌人自行踩险不推断为玩家击杀 |
| 自然熔岩、陷阱、饥饿、地火/气体扩散 | 原因类型明确，但责任者为 null，XP=0；不因玩家曾伤过目标而兜底抢归属 |
| 死亡爆炸/递归死亡 | 源为实际产生死亡效果的死者，不自动沿用杀死它的人。死者为队友且仍满足来源队伍合同才适用盟友分配 |
| 行政移除、局终清理、生成回滚 | 永远 0；没有 damage 也可能进入 kill，不能按事件次数发经验 |

队伍关系按稳定 ID/关系版本保存必要的离场摘要，死者来源无需保留活对象。队伍识别不是永久 `isAlly` 快照：效果创建时写稳定队伍/控制者 ID，兑付时检查同一关系仍有效；被解盟/转敌的效果不再给玩家队伍奖励。不存在合法队伍就给有资格的真实责任者，不把 null 当 player。盟友经验不会调用玩家 UI；它采用公开、确定的职业自动分配策略。转换前后的“敌我关系”应是新的只读事件字段，现有 CreatureView 不含这些资料，不能让模块拿活实体补查。

### 3.3 底座“伤害来源传播”补强

现有 `runtime.attacks` 只在 `CombatSystem.attack` 范围内可信，`afterAttack` 还早于调用者符文等后处理。反伤/分摊甚至可能继承攻击者而给出错误的非空值。保留其阶段 0 兼容观察意义，但 XP 改用强类型来源，**不以 sourceId 的非空作为充分证据**。

```ts
// 提议的类型，尚未实施；null 必须显式传播，不回落到当前 attack 栈。
type EffectOrigin = Readonly<{
  effectId: number; rootEffectId: number;
  actorId: number | null; // 机械效果来源，不覆写原 Bolt caster
  creditActorId: number | null; creditPartyId: string | null; // 扩展 XP 责任者
  kind: 'melee' | 'projectile' | 'bolt' | 'status' |
        'reflection' | 'reprisal' | 'transference' | 'displacement' | 'terrain' |
        'death-effect' | 'negation' | 'lifespan' | 'administrative';
  parentEffectId: number | null;
}>;
type DamageFact = Readonly<{
  targetId: number; hpBefore: number; hpLost: number;
  origin: EffectOrigin | null; damageKind: 'physical' | 'fire' | 'poison' | 'other';
}>;
// 仅引擎适配器可建立作用域；try/finally 嵌套清理，模块无权伪造。
withEffectOrigin<T>(origin: EffectOrigin | null, resolve: () => T): T;
```

直接路径显式传 origin；同步叶子可用嵌套作用域减少签名穿透，但离开作用域的状态必须保存纯 JSON 来源。`effectId` 由扩展运行时单调计数，不读墙钟、不用 RNG。直接致死赋值（例如否定）也要生成终结原因，不能等待不存在的正伤害事件。kill 在处理死者 DF 之前保存终结原因，在原去重后发一个死亡事实，避免递归死亡覆盖来源。

首版状态所有权采用“最后一次真正改变该状态有效值的施加者”；同一状态有毒伤叠加但未真正刷新/增强时不覆盖。无来源的环境重新施加并改变状态则写 null。此规则是公开、可测试的近似，不声称能按毒层贡献分摊；D02 选 C 时要改为逐效果贡献账本。状态清除/免疫/复活同时清来源，读档保存恢复。`BoltResult.caster`/`BoltWorld.caster` 当前保留原施法者，不能拿“最终被击中者”猜反射者；在 `BoltTrajectory` 真正反射决策点另记责任者 ID，不改 CE 原 caster/仇恨机械语义。这是扩展 XP 的新取舍，非原引擎既有归属。每次由生物成功反射都更新独立 creditActor 为该生物，多次反射以最后一次生物反射为准；无生物责任者的墙面/地形反射清 creditActor 为 null，不给墙另一侧原施法者兜底记奖。机械 caster 始终按原路径保留。地形扩散不记所有权：显式位移提交的紧邻落地伤害和死亡 DF 的同步即时爆炸允许携带对应位移/死者来源；这个有界作用域结束后，留在地图的地火/气体及之后传播一律 null。不是一进入 terrain 函数就无条件切断，否则会错误吞掉上表的即时位移/死亡爆炸归属。因此不需要为全地图气体体积做按来源拆分。

测试矩阵必须覆盖：近战、投掷、直伤、反射、反伤、延迟毒/燃烧、位移落地、自然环境、否定、递归爆炸、行政移除、施加者死亡/离层、状态叠加/清除、保存/seek。玩家死亡也需独立事实通知组件清理，但绝不复用“怪物 kill 就是所有生物死亡”的假设。

## 4. 等级、曲线与 26 层节奏

开始 L1，累计经验 T(1)=0；L→L+1 的费用为 `C(L)=40+20L+4L²`，L=1…19。累计阈值：

`T(L)=40(L−1)+10(L−1)L+(2/3)(L−1)L(2L−1)`。

实现用安全整数累加生成冻结表，避免浮点公式在读档边界差 1；展示 `xp−T(L)` / `C(L)`，20 级显示“已满级”，不用除 0。一次奖励跨多级时按等级递增逐项发点，最后只合并一条本地化消息。

| L | 1 | 3 | 5 | 8 | 11 | 14 | 17 | 18 | 20 |
|---|---|---|---|---|---|---|---|---|---|
| T(L) | 0 | 160 | 480 | 1400 | 3040 | 5616 | 9344 | 10880 | 14440 |

以上仅示范一组阈值。上限、费用表/曲线、逐级发点和自动生命增长来自配置；校验测试只证明安全整数、单调性、阈值边界、累计和多级跳升正确。旧稿的 D26 目标等级、10 种子/3 路线奖励普查与比例校准已取消，不作为任何小步验收条件。未来若单独批准平衡工作，再建立测量计划，不为凑等级目标修改经典生成。

本套样例中等级本身不加命中、不乘伤害、不造成等级压制：每级仅发点，每偶数级 +1 原生最大生命（满级累计 +10，因为包含 L2…L20）；样例升级回复配置为不回血、不回专注、不清冷却。1a 必须同时支持配置声明的回复/冷却重置选项，并前置派生差额同步和资源/冷却状态提交基础。体质等也不通过只读升级事件直接改 HP；由安全点的受控引擎能力同步派生值。

## 5. 属性与原生数值的关系

### 5.1 默认样例规则（由数据配置）

新增属性初始为 0，加开局职业/种族奖励。每项上限 8；下面的上限都是含技能/身世额外修正前的属性预算，最终合成还要过全局上限。

| 属性 | 明确效果 | 明确不影响 |
|---|---|---|
| 原力量 STR | 保留初始 12、药水 +1、虚弱及原装备需求算法；每 3 属性点 +1 训练力量，本局至多 +4 | 不再额外叠一层“每力量伤害百分比” |
| 敏捷 AGI | 普通有命中掷骰的物理攻击最终命中率 +1 百分点/点；作为防守者让对方 −0.5 百分点/点；潜行距离减 `floor(AGI/3)` | 不加行动速度/暴击/额外攻击，不改变必中或免疫 |
| 体质 CON | 每点最大生命 +3（最多 +24），由引擎能力同步到原 maxHp；升级/加点不恢复当前生命 | 不减毒、不免疫地形、不降低饥饿，不另加自然回血倍率 |
| 意志 WIL | 专注上限 `8 + floor(WIL/2)`（8–12）；主动技能冷却减 `floor(WIL/4)` 个客观块，但不低于原冷却的 75%（向上取整） | 不增加法杖伤害/次数、护符回复，不缩短 CE 负面状态 |
| 感知 PER | 主动/自动搜索的原 strength 输入 +2/点，最多 +16；仍沿原距离/可见/阻挡判定，不能穿墙揭示 | 不扩大 FOV、不揭示物品真名、不直接显示陷阱位置；成长搜索加值含技能/血统总计最多 +40 |

命中修正按整数基点合成：AGI 攻 +100bp、守 −50bp；经典命中率先计算完，再加修正并钳制 5%–95%；**原必中/必失分支优先，不插额外 RNG**。区分“原短路必中、不掷骰”和“原概率 100% 仍执行一次掷骰”（例如抓持、投掷克敌）：后者也不能钳成 95% 或省去原 RNG；策略输入需显式的 `rollMode: skip-guaranteed | roll-guaranteed | roll-probability`。经典 `hitProbability` 返回整数百分率时，最后向下取整到原掷骰精度，UI 使用同一公式。升级/体质派生最大生命 +10/+24，与力量训练的 +4 都是本局上限，不指数叠乘。

没有“伤害属性”之外的第五条隐式成长。物理伤害策略用于技能/被动，默认乘数 10000bp；所有 growth 加成相加后总增伤≤20%、单次减伤≤25%，乘法在既定一个槽位执行并向下取整，非零原伤害最低 1，原 0 仍为 0。禁止两侧技能各乘一次造成乘法爆炸。法术、毒、火、饥饿和熔岩不吃这个物理槽。

### 5.2 原数值的唯一所有者

`Player.effectiveStrength`、`Creature.hp/maxHp` 继续是引擎事实。模块存训练/体质/等级与“已应用派生差额”，引擎受控 `reconcileGrowthStats` 能力在确认加点/升级/初始角色完成后计算 `newBonus−appliedBonus`，只更新该差额。喝生命药水仍原生 +10，力量药水仍 +1；既不覆写药水所得，也不在 load 时再加一遍。

增加 maxHp 时保留原 hp；降低上限只 `hp=min(hp,newMaxHp)`。开局全部身世完成后才按新 maxHp 填满一次。读档校验 derived 与属性/等级一致，load 只绑定，不“修正”存档并偷偷治疗。

Monster 的变形、突变、强化、还原召唤者形态会直接重置原生 maxHp（`Monster.polymorph`/`applyMutation`/`restoreSummonerForm`，以及强化与克隆/分裂等），不能只接玩家升级。扩展引擎桥接在这些真实基值更新边界区分“原基础数值”与已应用成长：以扣除旧成长后的基值执行原形态变更，再加一次新成长差额；当前 HP 先服从原形态转换语义，再加回最大生命成长但不额外治疗。中间态只在同一引擎提交内，不能被观察/保存。保留 ID 的变形保留成长和奖励收据；复活沿原复活回血规则，不重赠点/经验。克隆显式继承战斗构筑而不继承未分配点/可兑现奖励，新的 rewardId 标为无奖且禁成长；克隆基础生命算法同样先排除旧成长、最后重算一次，不能将已带加成的 maxHp 当新基础。1b 覆盖这些路径，不把它们留成双加成隐患。Monster 没有 Player.strength 字段时，通用属性视图提供模板基础力量用于技能门槛；没有装备需求/力量消费规则的生物不会凭空多一层伤害。未来 NPC 装备接相同有效力量端口，不添加玩家专属经验字段。

### 5.3 策略端口：纯计算与引擎提交分离

事件仍是冻结 DTO、只准写自己的组件；它不能改 attackResult、HP、物品、地图。策略是另一个受限接口：只读组件视图 + 明确输入 → 有界标量结果；无 context 写权限，无 RNG/日志/命令/Promise。原骰子由引擎在原位置取。

```ts
interface GrowthRulePolicies {
  hitChance(input: Readonly<HitInput>, baseBasisPoints: number): number;
  physicalDamage(input: Readonly<DamageInput>, baseDamage: number): number;
  stealthRange(input: Readonly<StealthInput>, baseRange: number): number;
  searchStrength(input: Readonly<SearchInput>, baseStrength: number): number;
  derivedStats(input: Readonly<StatInput>): Readonly<{ strengthBonus: number; maxHpBonus: number }>;
}
// Input 含 actorId/targetId、只读属性/装备摘要、攻击种类、是否必中、
// 已公开的动作上下文；不含活 Creature/Game、可变组件或 UI 对象。
interface GrowthEngineCapabilities {
  reconcileGrowthStats(actorId: number): void;
  executeSkill(request: ValidatedSkillAction): SkillCommitResult;
}
```

能力不是所有事件都可随便拿到：由底座给 growth 的已校验命令/确定的升级结算阶段授权；调用范围当次有效，和现有 context 一样过期失效。模块先构造请求，底座/引擎再验证行动者、目标、消耗与世界条件后提交。策略返回 NaN/越界/Promise、引用变异一律确定性报错，不能静默随机容错。

| 端口 | 现有源位置/插入语义 | 阶段 1 限制 |
|---|---|---|
| 命中 | `Combat/Combat.ts` 的 `resolveAttack`、`resolveThrownWeapon`：原必中判断后、概率掷骰前 | 近战/投掷两路都接；不伪装成 beforeAttack 可改数值 |
| 物理伤害 | 同文件原基础掷骰/偷袭/武器附魔之后，原护甲特殊调整/护盾/转移之前的唯一扩展槽 | 明确不重复处理法术/反伤；零伤害/免疫语义保留 |
| 力量/最大生命 | `entities/Player.ts: effectiveStrength` 的原读法保持；新引擎桥接在分配/升级提交处差额更新原字段 | 不在 HUD getter、damage 事件、onLoad 内偷偷重算写值 |
| 潜行 | `Game.calculateStealthRange` 原光照/护甲/戒指计算末端、原下限钳制前 | 隐身恒 1 的早退保留；最终有光下限 2、原特殊下限 1 不变 |
| 搜索 | `Game.searchForSecrets` 的 strength 输入侧，`manualSearch` 与 `TimeCoordinator.playerTurnEnded` 自动搜索共用 | 连搜充能、可见性、距离衰减和原搜索 RNG 不重写；不加第二轮搜索 |
| 专注/冷却 | `TimeCoordinator.objectiveTimeBlock` 的原 100 tick 边界 | 新只读时间事实 + 扩展状态推进；不用 playerTurnEnded 次数当客观时间 |

D16 的“零开销原路径”验收按可审计的严格含义：经典沿原函数体、无新增策略对象/组件读取/代理分派/分配/RNG，不为每个格子/伤害建立 DTO。扩展适配器在新局组装或已有扩展入口分支选定；`CombatSystem.attack` 已有的 extensionHooks 分支可以选择扩展求值器，经典 `resolveAttack` 不加策略判空。投掷/潜行/搜索同理选择扩展入口，避免把统一可选回调塞进经典循环。若具体实现需要新的经典热路径分支或重构原 solver，先提出变更，不将“只加一个 if”冒充绝对零开销。允许共享现有纯计算 helper；不复制整份 Game；原调用形式（包括取出 attack 作裸函数调用）必须保留。

多模块将来同时改同一规则时，注册显式的槽位和优先级，依赖拓扑+模块 ID 稳定排序，最后统一封顶；阶段 1 只有 growth 一个规则提供者，未设计的冲突直接拒绝启用，不采用“最后注册者覆盖”。

## 6. 加点、命令与录像

每升一级 +1 属性点（L2–20 共 19）；每到偶数等级 +1 技能点（共 10）。初始职业赠送一个被动和一个主动，不占升级技能点。普通被动 1 点，主动 2 点；前置与花费显示在预览中。升级通知只提醒，不强制弹面板，不暂停在半个伤害结算内。

UI 草稿可来回修改/取消，不写模块；分配/洗点开关、退款/代价由配置给出，1b 实现原子校验与提交。以下是草图，不替代实际命令 schema；按“确认”后一次原子 `ext:command` 提交：

```json
{"module":"growth","action":"allocate","payload":{"revision":7,"attributes":{"agility":1,"strengthTraining":0,"constitution":1,"will":0,"perception":0},"learn":["growth.skill.brace"]}}
```

attributes 是本次增量，训练力量 1 消耗 3 点，其它每 1 消耗 1。revision 是该角色分配状态版本，用来拒绝重复点击/过期草稿，不使用全局墙钟或渲染次数。UI 只提交自己的玩家；模块命令不接受任意 actorId 给 NPC 加点。按已排序 ID 校验未知键、负数/小数/非有限数、总点数、上限、前置、重复技能、重复 revision；预检全过才同时扣点/增属性/学技能/派生更新。任一项失败全不变，0 tick、0 RNG，不用先扣再补。

`allocate` 合法时 0 tick；只在玩家可接收新命令、安全模拟边界开放，死亡/正在强制回合/未完成目标选择时不能从 UI 插队。`equip-skills` 保存槽位且耗一次原等待动作的时间，换装不清冷却/恢复专注；永久属性不来自技能槽，避免换装刷生命。已经学会的技能冷却按 ID 保留，卸下也走时钟。所有永久加点/装配/施技命令都经 `game.executeCommand('ext:command', JSON.stringify(...))`；恢复录像时同一 dispatch，不再弹加点 UI。

D22-A 已固定：从 1a 起在扩展新局建立后、首个玩家动作前录一条必需 `growth/create-character` 命令，不暗扩经典录像头。1a–1d 使用中性样例身份，1e 再开放身份选择（详见 §8）。未完成角色创建的局只能接 create-character/退出；不能走动/存为可续录正常局。该命令一次且幂等拒绝重复，验证职业/种族/信仰组合，完成初始化及派生 maxHp 填满；录像自动重放它，seek 包含它。菜单取消不创建局，不留下半配置。

现有每命令完整扩展 checkpoint 保留；记录组件、XP收据、专注、冷却、奖励身份和来源，不仅等级。测量 1k/5k/10k 命令录像与存档体积、seek耗时；增长超过线性预期或 10k 命令扩展部分超过 10 MiB 时提交另案，不在本阶段擅自删检查点。展示/打开关闭面板、目标预览、tooltip 不消耗 RNG，不录规则命令。

## 7. 技能：6 个被动 + 6 个主动

所有例子是本项目原创的阶段 1 默认样例数据，强度未校准，本轮也不校准。初版每项一阶，没有“技能升级的隐藏倍率”。被动最多装 3 个，主动最多装 3 个；门槛用加点后属性/等级，职业不给额外秘密乘数。

### 7.1 被动候选（各 1 技能点）

| ID / 名称 | 前置 | 精确效果与边界 |
|---|---|---|
| steady-hand / 稳手 | AGI≥2 | 投掷武器有命中掷骰时 +5 百分点；不增魔杖必中/飞行距离 |
| close-guard / 近身防御 | CON≥2 | 相邻敌人的普通物理攻击对自身 −3 百分点命中；不增加护甲、不中断必中 |
| careful-step / 轻步 | AGI≥2 | 原潜行距离 −1；不改变声音/路径/移速，不突破原下限 |
| methodical / 细察 | PER≥2 | 主动搜索 strength 额外 +5；自动搜索不加，仍不穿墙 |
| composure / 沉着 | WIL≥2 | 专注恢复间隔从 8 客观块降为 7；不改变法器/护符回复 |
| weapon-familiarity / 武器熟练 | L≥4 | 普通近战物理伤害 +5%，并入总加法预算；法术/毒/符文直接伤害不加 |

### 7.2 主动候选（各 2 技能点）

基础专注 8；每 8 个**实际推进的客观块**回 1（装沉着为 7），上限随 WIL；等待会正常消耗时间/营养并让敌人行动，不是菜单等待。每 100 引擎 tick 为一个客观块，CD 表以块表示，施放成功立即写 `readyAt=now+adjustedCooldown`，在引擎推进块后比较；玩家攻击速度不额外赠送一轮回复。已满时恢复余数归 0，切换被动不得清空/重复兑现已累积余数；加载只恢复。

| ID / 名称 | 前置 | 效果 | 专注 / 基础 CD / 动作耗时 |
|---|---|---|---|
| measured-strike / 稳击 | 无（战士起始可赠） | 对相邻可攻击目标一次普通近战，+10 百分点命中、基础物理伤害 −10%；不是必中，不添加 AOE | 2 / 6 块 / 原普通攻击耗时 |
| brace / 架势 | CON≥2 | 原地等待，接下来 2 客观块内第一笔非零直接物理伤害 −20%，使用即耗尽；毒/火/饥饿无效 | 3 / 10 块 / 原等待耗时 |
| withdraw / 撤步 | AGI≥2 | 向合法相邻格走一步，至随后 1 个客观块结束前对自己物理命中 −5 百分点；拒绝以攻击替代被占格移动，不穿墙/不传送/不无敌 | 3 / 8 块 / 原移动耗时 |
| hold-breath / 屏息 | AGI≥2 | 等待后 3 块内潜行距离 −2；主动攻击/投掷/施法立即结束，装备护甲与照明仍有效 | 2 / 8 块 / 原等待耗时 |
| survey / 勘察 | PER≥2 | 做一次正常主动搜索，本次 strength +10，不额外再跑一次搜索，不加连搜充能次数；结果只有原规则允许知道的信息 | 3 / 8 块 / 原搜索耗时 |
| pressure / 牵制 | WIL≥2，L≥4 | 对相邻目标普通近战，物理伤害 −25%；若命中且实际造成 HP 伤害，目标 2 块内下一次普通物理命中 −5 百分点，使用即消耗 | 3 / 10 块 / 原普通攻击耗时 |

技能临时效果的“下一次”消费由引擎提交后事实驱动：纯 `hitChance/physicalDamage` 查询不能扣层数，多次 UI 查询不能把架势用掉。需要有唯一 attack/effect ID 的 `ruleEffectConsumed` 提交事实；架势在第一笔正的、允许减免的直接物理伤害提交时消费，即使随后被护盾全吸收；原零伤害/免疫不消费。牵制只在实际普通物理概率求值提交时消费，原短路必中不消费。**每次单独命中结算立即提交消费，再进入同动作的下一次命中**，不延迟到外层命令末尾；否则多击会重复享受一次性效果。持续时间用截止块，不在读属性时偷偷过期写组件。

这组技能没有治疗、远程伤害弹、传送、隐身、护盾生成、充能或召唤；这些仍是 Brogue 法杖/魔杖/护符的领域。架势是一次物理承伤修正，不替代能吸收多种伤害的原护盾；屏息不是隐身；撤步不是闪避无敌帧，阶段 3 再设计体力/翻滚/弹反。所有技能复用攻击/移动/搜索的真实动作服务，不靠直接改坐标/调用 takeDamage 绕过装备、地形、确认与耗时。

### 7.3 触发与原子提交

桌面点击技能栏或打开“技能”选择器；首版不占用 CE 已有字母键/数字键，快捷键待列完整冲突表后再确认。手机点技能后点合法目标/方向，点空白取消。选目标是 UI 草稿；最终一条 `growth/use-skill {skillId,target:{kind:'creature',id}|{kind:'cell',x,y}|{kind:'self'}}` 进入录像，不录“第几个槽位”。确认危险动作复用原 requestConfirm 决策记录。

现有 `Game.applyCommand` 直接派发 ext:command，早于 `performPlayerAction` 的终局/模态/麻痹守卫。因此必须新增**引擎拥有的行动资格与提交能力**；模块自己通过一点 UI 禁用不构成守卫。

禁止以递归调用公开 `handlePlayerAction`/`executeCommand` 来实现一个技能，不形成嵌套输入录像；持久架势在组件中存，单击稳击的临时修正只在本次动作核心内有效。

命令处理顺序：引擎守卫及合法性/已学且已装/冷却/专注/玩家可行动/目标可见可达/原动作确认 → 原子扣资源并登记技能作用域 → 执行原动作的即时核心一次 → 提交效果/清理技能作用域 → 原规则登记耗时 → 恰好一次原时间推进。不得把含 `playerTurnEnded()` 的整段原 Game 方法包进技能作用域：同步模式会在作用域还开着时推进敌人攻击，动画模式又可能提前返回，导致两模式不同。需要把受控扩展动作桥分成即时结算和收尾两段，复用原动作核心/耗时 helper，经典调用顺序原样保持；底层现有动作入口是 `performPlayerAction`，`handlePlayerAction` 是命令包装器。拒绝、取消、过期目标不扣费不耗时不取随机；合法但未命中仍扣费并耗时。不允许把“先 prepare 技能”单独变成可存档状态，再靠下一条任意攻击消费。程序异常按原录像来源失效机制暴露，不能吞错后部分续局；预检解决可预见失败。`Game.playerRecoversFromAttacking` 的武器快慢耗时仍是攻击时间所有者；在 `playerTurnEnded` 前沿原耗时 helper 登记 ticksUntilTurn，保留速度符文 `-1` 免费行动语义，并按原路径一致更新 timeSystem.currentTick，不能先 endTurn 再补时间。动画/强制回合走同一推进器，等完整推进结束后才记录命令检查点。

为 NPC 共用规则，内部执行器接 actorId，但玩家公开命令不能伪造它。将来 AI 调同一个校验/技能执行器，不写玩家输入录像；AI 决定依赖引擎状态与实质 RNG，由玩家输入回放自然再现。阶段 1 不在原怪物 AI 中随机插入新主动技能。

## 8. 职业、种族、信仰与开局

这是通用角色身份，不是把 Player 变成独有职业类型。职业决定初始小额属性、赠送技能和推荐成长路线；种族决定小额初值/窄被动；信仰决定一个可选誓约。三个维度都不改变 CE 装備掉落/固定起始装备，不附加隐藏经验倍率，不改变基础速度或视野。

### 8.1 职业 4 例（各 2 点属性，总预算一致）

### 8.4 开局流程

主菜单沿主线刻符新局布局：规则模式选“扩展” → 职业卡（显示属性/赠技）→ 种族 → 信仰（默认无信仰）→ 汇总 → 开始。经典不加载这些数据或额外 UI。

开始时先验证完整选项，再调用既有扩展 startNewGame，紧接 `growth/create-character` 命令完成身份；首个世界行动前必须完成，初始组件只占位。生成的原世界/RNG 不由 UI选项改变；身份奖励本身不取随机。记录 `characterCreated` 与配置版本，save/load/seek 不再赠点或恢复满生命。推荐项是用户首次打开时的可撤销预选，不自动替用户提交加点。

## 9. 与原 Brogue 成长共存、玩家/NPC 共用

力量药水保留 +1 力量与原解弱效果，生命药水保留最大生命 +10、治疗/清状态，强化卷轴继续强化物品；原生成频率/保证规则不改。属性训练最多 +4 STR、等级最多 +10 HP、CON最多 +24 HP，装备的附魔/符文仍是主要构筑核心。新物理增伤≤20%、减伤≤25%，不叠加新法术增益，先从上限约束而不是随意稀释原掉落入手。

样例的已知相互作用（只保留风险说明，本轮不开展平衡观测）：

- 更多 maxHp 会通过原自然恢复公式间接提高绝对回血，虽然没有新增回复倍率；统计每层伤害/治疗/食物与死亡率，不能只比较面板生命
- 力量训练更早满足重武器需求，影响 netEnchant 和命中；对力量药水稀缺种子单独测试，不能把“3 点=1力量”视为已平衡
- 敏捷/命中、原武器附魔、偷袭一起可能让小额加成变强；技能伤害槽固定，测精确上下界与必中路径
- 探索经验可能促成冲层；26 层目标不能只按全清路径验证，首访奖励不因上楼重置
- NPC 和精英目前已有原始 HP/准确/防御/速度，给它们“等级”不等于再乘等级成长，否则双重缩放

共享规则的含义：所有生物使用同样 progression/attributes/profession/skills 校验、阈值、点数、策略和行动执行器。原普通怪物初次提交出生时挂 L1/0训练点的中性状态，显示用 `threatRank` 表达危险度，**不将原 CE 危险度伪装成已获成长等级**；未来精英可定义 L5/职业/已花点数模板，须过同样预算检查，其原生模板只作为基础，不重复自动强化。阶段 2 NPC 用同样组件和职业选择，可中立/同伴；阶段 3 才给敌方 AI 配技能与高等级模板。

盟友经分享 XP 自然升级，按公开职业计划自动花点（是同一确定性领域操作，不是假装一次 UI 输入），并使用同样 HP差额/命中端口；不给普通敌人因为时间流逝自动升级。无职业生物可以保留未分配点直到合法模板配置，不能由随机分配隐含消费 RNG。身体/移动/footprint 与成长互不推导，遵循 totalwar “任何 Character 共享规则”，而非共享玩家 UI 和全知信息。

## 10. 底座补强：生成事务、死亡生命周期、能力边界

### 10.1 两层嵌套生成事务

当前 `Game.generateDepth` 的 before/after 只是首次入层外壳；`MonsterLifecycle.ownedMonsterList` 插入即 attach/spawned。里面至少有 `GenerationCoordinator.generateDepth` 的楼梯连通重试、`BlueprintEngine.applyBlueprint` 的实体/地图回滚。只在最外层 afterLevelGeneration 打一个 commit 不够。

```ts
// 1a0 实际合同：token 以对象身份识别，不暴露可伪造的流水号。
type GenerationToken = Readonly<{ label: string }>;
interface GenerationTransactions {
  beginGeneration(label: string): GenerationToken;
  commitGeneration(token: GenerationToken): void;
  rollbackGeneration(token: GenerationToken): void;
}
// 底座严格后进先出；模块只得到提交事实，不得持有 Game/token/rollback closure。
// generationCommitted: {label, creatureIds}
// generationRolledBack: {label}（只读诊断，无 RNG/状态写权限）
```

在原事务快照建立处 begin，原成功分支 commit，原实体/地图恢复之后 rollback；子 commit 只并入父事务，外层失败仍全部丢弃。出生初始化按实体稳定 ID，缓冲事实按原产生次序（不能重排递归死亡），且必须在原实体编号最终确定后。生成中的 attach 仅绑定底座会话资源、暂存组件/出生描述，不发可变的 growth 出生钩子、不消耗模块 RNG、不发消息、不发 XP；外层 commit 后一次初始化。正常局内无生成事务的新出生直接提交。所有生成投机范围内可变模块事件（包括 example 的 kill）统一缓冲；不能只拦 growth 出生却让 example 先改计数/发消息。仅已提交实体的事实按稳定产生次序在外层 commit 后派发；回滚范围内的事件全部丢弃。模块不在投机范围运行，因此没有投机模块 RNG/日志需要“撤销”。这保持 example 在已提交世界的语义，不承诺投机回调的旧时序，也不修改原经典测试期望。

失败子事务丢弃新增 components/rewardId/来源/挂接强引用/扩展临时 ID；内部蓝图/楼梯重试的引擎随机消耗仍沿原规则，不倒带。1a0 外层进入失败没有提交任何楼层变化，连同旧世界恢复进入前 RNG；已成功生成后的模块发布失败也走此失败边界。原引擎实体 ID 是单调分配，失败会消耗 ID，不要新增回退/复用原 ID 的行为；即使扩展局部临时 token 将来复用，也不能让暂存 WeakSet/Set 把失败对象当成已提交出生。蓝图会修改已有物体时记录扩展侧写集，失败恢复旧值；事务期禁止扩展可见世界操作，减少日志/效果回滚面。`createMachineRuntime.checkpoint` 的 rollback closure 没有成功通知，事务边界必须设在 `BlueprintEngine.applyBlueprint` 成功/失败出口；`buildHordeMachine` 可在楼层生成外执行，也要包同样事务。对 machineRuntime.remove 的旧占位实体，按原引擎实际保留/恢复结果同步引用，不声称它现有 rollback 能还原所有行政删除。成功后读取/存档不能见到 open transaction；未关闭事务视作程序错误，不序列化半局。

1a0 除扩展侧暂存与原蓝图/尝试回滚，还在扩展楼层进入边界恢复旧世界和会话绑定；这不是任意 Game 命令的通用可回滚事务。新局数据/模块状态纯校验已前移到退休旧局之前，但不承诺任意 onNewGame/外部回调异常可重建整个旧局。

### 10.2 死亡与回收

原 `Creature.takeDamage`→`Monster.die`→`Game.killMonster` 存在递归 DF，死亡和物理移除不同步。`killMonster` 的 deathProcessed 去重必须保持；玩家终局另发生命周期事实。建议顺序：锁存终结原因 → 原死亡效果/原去重 → 一次 deathCommitted 事实与奖励排队 → 完成原列表/乘客/物品处理 → 最外命令安全点结算奖励/回收。该安全点必须在同步/动画/强制回合的完整推进和最终视野更新之后：同步实时输入在 `recordInputEvent/updateRecordedCheckpoint` 前，同步回放在 `completeReplayEvent` 前，动画输入/回放在 `Game.finishAdvancement` 排空强制回合之后、其最终 `updateRecordedCheckpoint/completeReplayEvent` 前；非耗时 allocate 等命令也经过这个提交尾部。不能用 Vue 动画回调或仅函数返回当命令结束。HP≤0 不是能立即删除组件的证明。

在命令结尾或新局生成外层提交的安全点，从现有 WholeRunSnapshot 实体图的同一枚举逻辑取保留集合：玩家、当前/缓存楼层、休眠、携带乘客、待坠层、炼狱/复活引用，再加未结算效果来源引用。生物/组件图递归去重，ID稳定。仍可能复活的本体保留完整成长，永久离图的对象解除 hooks、runtime.creatures 强引用及组件；`spawned WeakSet` 不作为可达性证明。

死亡事实所需只读墓碑（ID、终结来源、奖励已兑现）与复活完整组件区别保存；不持有活对象。XP 收据和仍被 DOT 引用的来源摘要可以比实体活得更久。收据在局终统一丢弃；来源效果过期且无引用就回收，绝不按“离开当前楼层”回收。不在 snapshot() 中边保存边 GC，不在 onLoad 中改状态/RNG；读档仅校验 growth 引用、重建会话绑定，不删改序列化组件，必要回收等下一次模拟提交。growth 专用校验拒绝自身非法孤立引用，不擅自收紧阶段 0 其它模块的旧组件合同；恢复绑定不重复出生/死亡/奖励。

### 10.3 其余窄能力

- `itemKnowledgeChanged`：源于真正知识提交；只发合法新获知的种类摘要，不把未知种类送给显示层；覆盖使用鉴定/卷轴鉴定/自动熟悉，不覆盖取消或重复获知
- `objectiveTimeAdvanced`：区分实时客观块与入层模拟补跑；只有实时推进增加 growth 单调时钟，补跑不重复恢复专注或冷却。离层生物用截止时刻比较冷却，但不凭空把所有缓存层逐 tick 执行 AI；专注只为本轮参与模拟的生物累计
- `ruleEffectConsumed`：引擎实际动作提交后通知消费一次性效果；纯策略永远只读
- `creationReason` / `rewardId`（1a）：从生成/召唤/分裂/周期刷怪等真实创建入口传播，不能用当前怪物种类猜“是否召唤物”；1a0 的出生事务不能冒充已完成奖励资格接线
- `characterCapabilities`：只读主角/队伍/基础模板/可行动摘要与命令能力；严格白名单，不能给模块完整 Game 引用

优先使用 extensionRuntime 内的状态/会话缓存与现有扩展快照；**若必须给 Game 加任何字段，先登记 `scripts/u03-state-contract.json` 并说明初始化/重开/读取/快照归属**。Creature 回调沿现有 WeakMap 接线；不靠临时挂 JS 属性绕过状态合同。经典无这些组件、事务、来源表、时间钩子或快照键。
