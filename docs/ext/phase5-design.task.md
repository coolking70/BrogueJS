# 阶段 5 设计任务书：远征营地、聚落建设与世界层（联合设计稿）

> 分支 `ext/phase5-design`（基于 ext/foundation `9331104`：阶段 1–4 开发完成，阶段 3/4 统一收尾门禁另行进行）。本轮**只出设计稿，不改代码/测试/数据，不 commit**。
> 维护者原定阶段 5 为“多层战场与世界地图”（`docs/ext/README.md` 阶段表、`references/totalwar-notes.md`）。现新增“聚落建设”方向，要求与阶段 5 **联合设计**，边界由维护者侧（Claude）判断，见下文“建议边界”，请审计代码后确认或提出更优方案并说明理由。

## 维护者需求（2026-10-06）

1. 简化版 Minecraft/泰拉瑞亚/辐射4 式建设：采集资源、合成道具装备、建造设施；用建材合围并加装屋顶形成房屋，设置门窗，放置家具；招募 NPC 进行日常种植、生产与聚落防御；随范围扩张与人口增长逐步形成城镇。
2. **地牢任意楼层都可以建营地**（不只地表）：支撑“地牢远征”玩法——在深层建立营地以采集资源点、提供中途补给，避免深层探索时每次都要回地表回收与补给，也不依赖传送（传送尚未实现，可作为后续扩展点）。
3. 可能涉及更大规模的策略玩法（世界地图、部队/多格单位、战场），需与原阶段 5 统一考虑。
4. 工作分配要考虑**并行开发**以提高效率；注意 dot（云端 Codex）的每次沟通都需要维护者手动转贴，dot 只适合承担**大块、自包含、边界清晰、决策点少**的模块任务；其余默认由本地 Codex 实施、Claude 审查集成。

## 建议边界（Claude 的判断，请审计后确认或修正）

拆成 1 个底座能力包 + 若干独立模块，按依赖分轨，便于并行：

| 轨道 | 内容 | 归属 | 建议执行者 |
|---|---|---|---|
| 5A 持久世界底座 | 楼层持久化保证（已访问层的长期存在、营地所在层不被清理）、**离线结算框架**（玩家不在场的层按经过时间确定性一次结算，不后台常驻模拟、不破坏录像）、结构编辑原语（墙/屋顶/门窗层、受控地形写入、**房间识别**：闭合+屋顶→房间及其功能标签）、NPC 日程/工作调度底座、资源/存储容器底座 | 底座 | 本地 Codex |
| 5B 资源与合成 | 资源点（可再生采集点）、采集动作、材料物品、配方/工作台、合成装备与道具 | 模块 `crafting` | **dot**（自包含，契约清晰后长时间独立开发） |
| 5C 营地与建造 | 任意楼层建营地（营地范围=owned region）、建造模式、房屋/门窗/家具、补给储存、营地与远征循环 | 模块 `settlement` | 本地 Codex |
| 5D 招募与工作 | 招募 NPC（可与 narrative/growth 软联动）、种植/生产/搬运/守卫工作、日程、离线产出 | `settlement` 内或独立 `colony` 模块（请判断） | 本地 Codex（可在 5A 后与 5C 并行拆分） |
| 5E 防御与袭击 | 袭击事件、守卫、与 combat/giants 软联动 | `settlement` 子步 | 视情况 |
| 5F 世界层与战略 | 原阶段 5：世界地图 → 区域 → 战场 → 个人遭遇，部队用多格单位/群体表示；城镇作为世界节点 | 独立模块（如 `worldmap`/`strategy`） | **本轮只出高层分层与接口预留**，详细设计在 5A–5E 落地后另立 |

## 设计稿必须回答
1. **核心循环**：地表聚落 + 地牢远征营地的节奏；与 Brogue 的下潜、饥饿、死亡、楼层生成如何协调（哪些原规则在启用这些模块时调整，哪些保持）；不启用模块时原游戏不受影响（零影响合同）。
2. **任意楼层营地**：营地如何建立/拆除/限制数量；营地所在层的持久化与离线结算；补给与储存；远征中营地之间的移动（步行/楼梯，传送作为后续扩展点）；营地被袭击或玩家死亡时的处理。
3. **时间模型**：在场层逐 tick、离场层离线一次结算的确定性规则（输入：离开时快照+经过时间+随机种子派生；输出：产出、消耗、事件），录像/seek/读档一致性。
4. **建造规则**：格子上的结构层（墙/屋顶/门窗/地板）、建材与耐久、房间识别算法与功能判定（卧室/仓库/工坊/农田等由家具决定）、对视野/寻路/地形效果（火、水、气体）的影响、拆除与损毁。
5. **资源与合成**（为 5B 提供可直接开发的契约）：资源点数据、采集动作与耗时、材料物品、配方/工作台/产出、与现有物品系统的关系、模块独立性与软接口。
6. **NPC 招募与工作**：招募来源（narrative NPC、救出的俘虏、新生成的居民）、工作类型与日程、需求（食物/住所）与满意度（是否需要）、离线产出、与 growth 等级的关系、上限与性能预算。
7. **防御**：袭击触发、守卫行为、与 combat（预警/韧性）和 giants（大型袭击者）的软联动。
8. **城镇与世界层**：人口/范围阈值、城镇阶段能力；世界地图与战场分层的高层草图、部队如何复用 4d 群体模型；本轮只定接口预留。
9. **UI**：建造模式、摆放、配方、营地管理、NPC 分配，刻符风格与 320/390 手机可用性。
10. **持久化与性能**：存档体积、营地数量/NPC 数量/结构格数上限、离线结算成本。
11. **模块拆分与依赖图**、**共享文件触碰清单**（与阶段 3/4 收尾的冲突评估）、**分步实施计划**（每步可独立验收、可停下）、**并行开发排期**（哪些轨道可同时进行、谁执行、合并顺序与冲突点）、给 dot 的任务应满足“自包含+契约先行+决策预先给定”。
12. **待维护者决定的问题**：编号列出，每题 2–3 选项与推荐理由（例如营地数量上限、离线结算粒度、是否有居民需求系统、袭击是否默认开启、地表家园是否必需等）。
