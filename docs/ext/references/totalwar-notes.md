# 参考笔记：totalwar 项目的多层战场与世界模拟设计

> 用途：为 BrogueJS 扩展模式的阶段 5（多层战场与世界地图）提供设计参考。
> 来源：维护者本人的项目 totalwar（"修仙开放世界战争 RPG"，Unity 3D）的设计总纲 `docs/PROJECT-HANDOFF.md`，由 Claude 摘要并改写为适合 Brogue 字符画面的方向。原项目是 3D 实时，这里只取设计思想，不取技术方案。

## 1. 原项目的核心设计思想

1. **玩家是世界中的一个人，不是世界的操纵者。** 世界在没有玩家时也自行运转：国家、宗门、家族、人物自行发展、结盟、开战、衰亡。玩家的影响力由实力、身份、职位、声望、人际与所属势力决定——"爬到那个位置，才拥有那个位置的权力"。
2. **路线开放。** 不存在唯一正确路线；散修、宗门弟子、将领、商人、邪修等都应是完整玩法。
3. **时代由世界状态推动。** 太平 → 暗流 → 乱世 → 大争 → 大劫，由势力差距、战争次数、高阶人物死亡、资源危机、玩家行为等共同推动，而不是按时间硬切换。
4. **战场分层模拟。** 不让所有士兵运行同等精度的 AI：
   - A 级：玩家、重要人物、Boss、玩家附近的重要单位——完整规则与 AI。
   - B 级：玩家附近的大量普通士兵——简化 AI、简化战斗。
   - C 级：远处大军——只做编队移动与战线表现。
   - D 级：宏观军团——只是"第三营 823/1000"这样的数据：人数、战力、士气、编队、位置、目标、战损。玩家靠近时逐级提高精度。
5. **身份决定指挥权。** 普通士兵没有军队界面；小队长可下"跟随/防守/推进/撤退"；将军可控制多支部队和战术目标；最高领导才有接近大战略游戏的决策权。功能随社会身份自然出现。
6. **战争中的自由参与。** 战争是世界自行发生的事件，玩家可以参军、接任务、护送、暗杀、侦察、破坏后勤、观战、趁乱偷盗、战后搜刮（"战场捡漏"），也可以直接离开。
7. **信息不全知。** 玩家掌握的战况受身份、神识、情报网与人际影响：凡人只知"西边有仙人大战"，长老知道参战人数与伤亡，情报头子知道具体人员与去向。
8. **玩家与 NPC 共享规则。** 数据结构上玩家也是 Character，属性、修炼、技能、装备、战斗、人际与 NPC 尽量共用，避免"玩家专属宇宙规则"。
9. **NPC 行为由规则驱动。** Utility AI、状态机、规则系统、数据驱动决策，不用 LLM 驱动全部 NPC。

## 2. 改写为 Brogue 字符画面的方向

Brogue 的优势是"一屏字符就能表达复杂局势"。分层战场正好对应**不同比例尺的同一种网格**：

| 层级 | 一格代表 | 画面内容 | 对应原项目 |
|---|---|---|---|
| 世界地图 | 一个区域/城池 | 地形大块、城池与宗门符号、势力着色、军团标记、事件标记 | 世界模拟 + D 级 |
| 区域/战役图 | 一片战场区域 | 部队方块（多格单位，见阶段 4）、战线、补给线 | C/D 级 |
| 战场 | 一小队或若干士兵 | 部队以"字符簇"表示，士气/人数用颜色深浅表示 | B/C 级 |
| 个人遭遇 | 一个人（即现在的地牢网格） | 完整 Brogue 规则：玩家、精英、Boss | A 级 |

关键交互：
- **缩放即切换精度。** 玩家在世界地图上走进一场战役，就"放大"进入战场层；在战场层接近敌方精英，就进入个人遭遇层。离开时，个人层的结果写回上层的数据（人数、士气、战损）。
- **低层结果汇总到高层，高层状态驱动低层生成。** 战场层的地图由区域地形生成；个人遭遇层的地图由战场局部生成，并带上该处部队构成。
- **指挥界面随身份出现。** 字符界面的"命令栏"在玩家成为队长后才出现部队指令项，成为将军后出现多部队与目标选择。
- **情报迷雾。** 世界地图上的军团标记可以是"未知规模的军队"，精度随情报提升。

## 3. 给 BrogueJS 扩展的建议

1. 阶段 5 体量最大，先只做**设计文档 + 世界地图原型**：一张可行走的区域网格、几个势力着色、军团作为可移动标记、点进军团标记生成一张战场图（可以先复用现有地牢生成器换主题）。
2. 部队表示依赖阶段 4 的多格单位能力：一个部队 = 一个占多格的单位，其"人数"决定占格数或字符密度。
3. 世界模拟（势力、时代、人物）先做成纯数据 + 规则的回合推进，不接入地牢回合；与地牢层之间只通过"进入/离开时的结果结算"交换数据，保持低耦合。
4. 玩家与 NPC 共享规则这一原则与阶段 1（RPG 成长）直接相关：等级、属性、职业、种族、信仰应设计成任何生物都能拥有的组件，而不是玩家专属字段。
