# 参考笔记：Lost Flame 的大型敌人与类魂战斗机制

> 用途：为 BrogueJS 扩展模式的阶段 3（类魂战斗）、阶段 4（大型敌人）提供设计参考。
> 来源：维护者本地持有的 Lost Flame（Java 回合制 roguelike，商业游戏）安装包中的数据字段与类名，由 Claude 用自己的话归纳机制。
> **版权边界**：Lost Flame 的代码、数据文件、文本、图像与音效均不得复制、上传或移植进本仓库；这里只记录玩法机制层面的观察，实现必须自行设计。具体数值不作参考依据。

## 1. 整体印象

Lost Flame 是"Brogue 式网格回合制 + 魂系战斗节奏"的结合：仍然是一格一步、回合推进，但战斗围绕体力、出手时机、敌人预警和大体型敌人展开，并有篝火、灵魂（经验/货币）、升级加点等魂系元素。它证明了"类魂"在纯网格回合制里是成立的，关键是**把动作游戏里的"读招"变成"读格子"**。

## 2. 生物数据模型（观察到的字段，用于启发我们的定义格式）

敌人定义是数据驱动的 JSON，每个敌人大致包含：

| 维度 | 观察到的字段 | 对我们的启发 |
|---|---|---|
| 体型 | `size`：1、2、3、4（约 150 种敌人中，1 格约 90 种，2 约 33 种，3 约 22 种，4 仅 2 种） | 体型是一等字段；2×2、3×3 是主力，4×4 只给极少数 Boss |
| 身体类型 | `body`：beast / humanoid / bird | 决定可装备、可被哪些效果作用、动作表现 |
| 行走方式 | `walkType`：如 water（只在水中行动） | 大型敌人常与特殊地形绑定（水生九头蛇、地底蠕虫） |
| 基础属性 | hp、speed、strength、dexterity、level | 敌人与玩家共用同一套属性体系 |
| 魂系属性 | `stamina`（体力）、`resolve`（意志/抗性）、`attackQuickness`（出手速度）、`tenacity`（韧性）、`moveCost` / `attackCost`（行动耗时） | 见第 4 节 |
| 抗性 | fire / cold / poison / acid / dark / light / lightning / petrify / polymorph 等 | 元素抗性表，按需取子集 |
| AI | AI 类 + 参数串，如 `hostile,brave,seesAll`、`distance-3`（保持距离的射手）、`immobile`、`dodgeDesire`、`noAngryOnHit`、`huntItems-10`、`behindFighter`（躲在近战后面） | AI 由"基础行为 + 可组合的性格参数"构成，非常适合数据驱动 |
| 攻击 | 每个攻击有伤害骰、命中、文本键、音效、附加效果钩子（如 `#onAfterStrike:...`） | 攻击与"命中后效果"分离，效果用事件钩子挂接 |
| 技能 | 字符串引用的技能/被动，部分带参数（如"多头：9"） | 技能注册表 + 参数 |
| 掉落 | 物品表，支持"或"分支与骰子数量 | 掉落表格式 |

## 3. 大型敌人（阶段 4 参考）

- **体型即占格**：size=N 的敌人占 N×N 格。体型越大越少见，基本都是精英或 Boss。
- **专属场地**：存在以大型敌人为主题的区域模板（如巨人主题区域），说明地图生成会为大体型敌人准备足够开阔的空间。我们需要：生成时保证 Boss 场地的最小净空、通道宽度足以让 N×N 单位通行或明确让它被困在场地内。
- **多段身体**：观察到"蠕虫头 + 不行动的蠕虫身体段"这类拆分，说明长条形敌人可以用"一个主控实体 + 若干跟随的身体段实体"实现，而不是一个不规则形状。这是比"任意形状占格"简单得多的方案。
- **多头机制**：九头蛇类以"头数"为技能参数，暗示"一个大体型单位每回合可以有多次攻击/多个攻击来源"。
- **Boss 血条**：有独立的大血条显示（类名 BigHPBar），大型敌人需要专门的 UI 呈现。
- **体型影响受控**：观察到"畏惧大体型"之类的 AI 欲望，说明体型差会影响 AI 行为（小怪远离大怪、或大怪威慑）。

在 BrogueJS 中实现时要解决的问题（Lost Flame 不能直接给答案）：
1. 占位：网格上一个生物占多格，所有"某格上的生物"查询都要改为查占位表。
2. 寻路：按体型膨胀障碍（N×N 单位只能走"N×N 都可通行"的位置），需要按体型缓存距离图。
3. 视野与目标：玩家看到任一格即可见；攻击/法术命中任一占格即命中。
4. 渲染：大型敌人用多格字形拼图或放大字形。
5. 地图生成：Boss 场地蓝图 + 通道宽度约束。

## 4. 类魂战斗（阶段 3 参考）

- **体力 stamina**：攻击消耗体力（类名 AttackCostByStamina），体力不足会限制连续行动。敌人也有体力，Boss 的体力池很大。
- **出手速度与行动耗时**：`attackQuickness`、`moveCost`、`attackCost` 说明行动不是"一回合一动"，而是按耗时结算——重武器慢、轻武器快。Brogue 本身已有"移动速度/攻击速度"概念，可以扩展而不是推翻。
- **意志 resolve 与韧性 tenacity**：对应"抵抗硬直/控制"的能力，接近魂系的韧性（poise）。
- **预警格（最关键的机制）**：有一批"多段动作"类——冲刺（Charge）、突刺（Lunge）、重砸（BigSmash）、突刺接重砸、突刺接跳越、双段挥砍——并配套"TileShower"类，即**在敌人出手前一回合，把即将被攻击的格子标出来**。玩家的应对就是读格子：走出范围、或在出手前打断。这是把动作游戏的"看前摇闪避"翻译成回合制的核心手段。
- **格挡与弹反**：存在格挡（如"阻止对方贴近"）与"弹反失败"相关类，说明有弹反判定且失败有代价。
- **闪避欲望**：AI 参数 `dodgeDesire` 表示敌人也会闪避。
- **篝火**：营地类区域细节（Campfire），对应魂系篝火：恢复、复位、可能刷新敌人。
- **灵魂**：有"灵魂窃取"类减益，说明灵魂（经验/货币）是可被夺走的资源，接近魂系"死亡掉魂"。
- **升级**：有升级效果、升级辅助与"升级时鉴定物品"等逻辑，说明升级是带加点选择的成长节点。

## 5. 给 BrogueJS 扩展的建议

1. 阶段 3 先做"预警格 + 多回合攻击"这一项，它最能体现类魂、对现有规则改动最小（只需要"敌人进入蓄力状态 → 下回合结算"的状态机和显示层）。体力、韧性、弹反在其后叠加。
2. 阶段 4 先做 2×2，跑通占位、寻路、视野、渲染、生成全链路后再推广到 3×3；长条形敌人用"主体 + 身体段"方案。
3. 敌人定义格式借鉴其"基础 AI + 可组合性格参数""攻击与命中后效果分离""体型/行走方式为一等字段"的结构，但字段名与数值自行设计。
