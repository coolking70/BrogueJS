## 范围

1. 群体底座：开放 group 能力门——一个核心（任意已开放刚体）+ 若干成员实体（各自刚体，通常 1×1 或小形状），群表持久化；成员有独立 HP、局部状态、位置、受击、攻击冷却。约束：成员相对核心的牵引距离/连接拓扑（树），移动中的中间态也须满足约束。
2. 调度：TimeCoordinator 三处遍历只含独立生物与群核心（成员仍在原生实体列表以便受击/环境/codec）；核心激活时选择“核心移动+成员落脚”或“有界攻击子段束（≤4，并行耗时取 max）”；成员冷却随真实 soonestTurn 递减；无合法动作也付正耗时，不 0 tick 自旋。与 3a0/3b 的 actor-action 调度对接：复合体的 phased 招式由核心作 decision/time owner，来源为具体成员（sourceEntityId/partId/generation）。
3. 落脚规划（§4.3）：核心先迈一步，再按约束树与 partId 稳定顺序为成员选落脚点（每成员 ≤32 候选、≤128 回溯，扫掠检查，禁止成员互相交叉穿过），预算耗尽 → blocked，有界重选；不隔墙瞬移成员。场地生成按 D 决策“以生成保证体型可通行”为基准，正式内容场地须对整组实际验算。
4. 受击与传伤：命中成员按 part 路由（D08；横扫两腿各一次、火球覆盖多腿各一次、整体精神效果 group 一次）；成员 HP 扣减后按 **1:4** 传核心（D09=A，基数取 min(防护后伤量, 命中前成员正 HP)，不重投、不重复符文/反伤/growth/阶段 3 消费）；直接打核心只扣一次。
5. 破坏与修正：成员 HP=0 → 唯一破坏收据，**不 kill/XP/死亡 DF/掉落**，默认 remove + 槽位墓碑（释放占位）；破坏修正从破坏集派生且幂等：腿少→移动 tick 倍率增大、头毁→禁对应攻击、支撑数 < minSupportParts → **immobile 但保留可用攻击（D15=A）**；`combat.part-break.v1` 软接口沿 4c（combat provider 未接时用 fallbackStun，互斥）。核心 HP=0 才整体终结一次（XP/击败事实按 group 一次），成员按无死亡路径批量退休。
6. 状态归属：数据分类群体级（精神类：魅惑/纷争/恐惧/麻痹等）与成员级（燃烧/中毒/缠绕等），群状态只一 tick。
7. 关系与被动转换（无 Boss 免疫，D07=A）：支配/纷争作用于整组；被动 polymorph 对整体（D16=A），单体↔复合体互转保留核心 ID、新成员先求位、消失成员无死亡退休，整体原子或整体无效；clone 复制整组（全新 ID、深拷贝、无奖励权利）；坠落/换层整组迁移或按 §4.2 合同 pending。
8. 渲染与 UI：核心 + 成员身体公开绘制（核心主字形、成员小字形/轮廓），成员可单独瞄准/检视，Boss 血条显示核心 HP 与成员存活/破坏概况；部分可见裁切；320/390 可读；历史帧隔离。
9. 正式内容：一个原创复合体敌人（建议“八足蛛”式：2×2 核心 + 8 条 1×1 腿，或“多头蛇”式：核心 + 3–5 个头），数值临时、数据驱动，配场地模板（实际验算整组可通行）与自然验收种子；无 growth/combat 也能击败。

不做：主动转换/阶段换形/分裂/召唤（4e）、成员再生（D13=A 关闭）、残骸地形、镜像。
