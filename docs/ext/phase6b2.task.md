## 3 功能合同与遗留闭环

### 3.1 游戏面板和输入

1. **入口与生命周期**：复用原生背包/检视入口及模块工具栏；如宿主缺通用物品扩展插槽，新增通用贡献，不在共享组件硬编码loot导入。无loot时不出现空面板/死按钮。floor/pack/equipped/container位置真实；容器缺席时无入口。关闭、死亡、换局、load/replay/seek时释放旧ID、选中项、事件监听与草稿，不能把上局选择提交到新局。
2. **详情**：显示可信名称/铭文、稀有度、已知属性、逐行词缀、熟悉度及可执行动作；长行可展开，未知行只给占位。原生附魔与loot enhancement不得混淆；6B3未实现的固定符文强度不能作为已经生效的比较收益。原生非loot装备仍可作对照，不为显示而补造moduleData。
3. **比较**：武器/护甲与当前对应槽；戒指分别列“替换左戒/右戒”，支持空槽、同基底两件、已装备候选与原生对照。现有六标量必保留；建议新增命中值、移动耗时、恢复、减伤/抗性、潜行/感知/光照、资源与寻宝等实际可用项，先冻结“键/单位/好坏方向/条件/可用能力”表。命中值不冒充无目标命中率，耗时降低才是改善；条件、符文、封顶和未知影响单独说明，不把原始修正相加当最终差值。
4. **来源说明**：只列已知来源和公开可解释的最终结果；源ID仅用于内部稳定身份，转成玩家可理解的槽位/物品/效果名。不输出raw moduleData、隐藏词缀ID、隐藏值、未鉴定专名或由总量反推的隐藏差值。属性知识变化须刷新详情/比较，但不能凭UI访问揭示知识或增加机械revision。
5. **过滤**：区分本地列表筛选与影响自动拾取的持久过滤。后者展示稀有度/类别/自动拾金、默认值、应用/取消/恢复默认草稿；仅应用时发`set-filter`。同值刷新不吞用户草稿；真实revision变化须提示重载或重建，不偷偷覆盖。过滤影响自动拾取，手动拾取仍可越过；列表筛选不得利用隐藏词缀或未知戒指种类。
6. **分解**：当前背包候选的单件/1–26件批量选择、全选可分解项、取消选择、已知产量或可信区间、费用、成功/拒绝反馈。装备中、粘装、地面/容器对象不能直接分解；需要取回时仍走原有命令。唯一品事前Yes/No，No零成本，Yes不返唯一收据；批量为一个原子命令，不逐件循环提交。未知分解区间不泄露隐藏腐化、物等或精确产量。
7. **鉴定**：显示碎片余额和10片/100tick费用；资格来自宿主`canBeIdentified`，不能用`affixes.every(known)`代替。否定后未知种类戒指、仅符文未知仍可操作；全已知/不足/陈旧目标拒绝并给明确反馈。原生鉴定、装备/卸装/拾取等复用`executeItemCommand`，不新造机械入口。
8. **输入与反馈**：模态接管方向键、背包字母、i/d/a/j/./x等游戏键，Esc按层返回/关闭，确认按钮保留Enter/Space原生行为，触屏一次触发一次。宿主ACK、确认、动画忙、回放只读与其它模块面板互斥遵守现有路由；提交期间禁重复、保留反馈，等待真实命令收尾后刷新，不能因返回void就宣称成功。营地异步链发布保护及失败反馈/键盘隔离不得回退。

### 3.2 不可破坏的状态与知识边界

- 写状态继续走`executeCommand('ext:command', JSON.stringify({module:'loot',action,payload}))`/`executeItemCommand`。β的key由受控适配映射为本会话itemId，提交时重验revision、所有权、装备、数量和容量；不按行号/名字识别物品。
- `set-filter`零tick但录像；分解每件100tick；碎片鉴定十片/100tick。非法/取消/陈旧/失败不部分扣费、不推进机械时间或实质RNG；成功付费动作可以正常推进世界及RNG。UI草稿不入存档/录像，不占Game持久字段。
- 所有Vue props/视图模型只接可信已知DTO。地面保守投影、未知戒指、侦测极性、腐化与当前诅咒的区别、幻觉/记忆分支继续守住；无可靠诅咒暴露事实时保持保守，不借面板扩展权限。不得先把raw数据传给组件再用CSS隐藏。
- 查询、展开、比较、排序、预览、来源分解不能改世界/双流/allocator/知识/实质时钟或录像。绘制缓存可按已有会话合同失效，不允许查询触发机械reconcile或新的事务。
- 同版本save/load、replay、seek、续录保持确定；旧版本/缺包/坏数据严格拒绝且保活局。新增Game字段须登记U03；worldSdk/edibleSdk冻结不解冻，必要C6/统计/宿主接口变化单列合同及新散列。
- 生产挂载后，旧“loot-item-card/loot-compare不得进入dist”已不成立；只将该前提改成**画廊、fixtures、tools/preview和调试入口不入生产**，保留未启用/未安装中性及预览隔离断言，不整删inert测试。

### 3.4 M4：真实力量与怪物侧重新平衡

历史已批准方向是不压词缀、用monsterScaling抗衡；原型武器代理忽略力量/鉴定/攻速，`12+floor(depth/3)`或`/4`仅是假设。6B1接入原曲线不是平衡验收；本步须产生当前实现上的测量和曲线裁定。

1. **先冻结测量口径**：推荐锚点D1/5/10/15/20/26，三预设；固定少量种子与当前版本真实生成物品，按实际装备限制选择同一武器+一甲+至多两枚不同戒指。登记角色真实力量、原生附魔、熟悉/鉴定状态、成长配置、怪物类型/层深/招式和选装规则。低/中/高装配样本不得通过四个独立最大值拼成不存在的装备；另列全知上界与正常知识状态。
2. **测真实路径**：实际StatPipeline、命中/伤害/时钟/恢复和怪物生命求值；至少输出伤害范围、命中、攻击tick、击杀所需动作/时间、承伤/可承受攻击、恢复/EHP代理、力量不足与封顶影响。EHP代理与实战结果分列。以当前未调曲线为A、候选为B，在相同输入上对比；无loot对照只作本项目参考，不做CE对照。
3. **有限场景**：loot单开主场；loot+combat和loot+giants各选直接相关代表场景，验证倍率与招式/遭遇叠加，不扫模块组合。正常模式真实力量路线用于平衡判断；6B1 seed26 wizard链只用于功能/录像，不能作为正常难度样本。固定装配实验与自然游玩路线在报告分开标注。
