## 2 必须保持的执行合同

### 2.1 权威边界与输入

- `Game.player` 永远是主成员；所有动作和确认先绑定 actorId，不借 focus/leader 推断。唯一实体、库存根、计时所有者和单活动层保持；普通冻结成员不参与窗口、不扣状态时间，居民经济沿原有世界时钟运行。
- 所有改状态输入经 `executeCommand` / `executeItemCommand`。窗口是一次外层输入事务，内部复用 P1a actor prepare/commit 和受信任 scope，不递归提交公开命令，不给成员额外运行 Monster AI，不把世界推进按人数重复调用。
- 接受前验证 schema、seq/revision/startTick、发行槽、成员权限、全部静态引用及计划长度；非法批次零写入、零 RNG/allocator 消耗、零有效录像前缀变化。`keep + null` 保留，`replace + null` 清空，keep 携非空计划拒绝；遗漏成员按 keep 规范化。同 actor 重复行、超限、未来 AI/网络负载明确拒绝。
- 每次取步重新验证目标、占位、物品根/容量/预留/冷却和风险。运行期失效产生硬停并保留失败步供修订；不跳过错误步、不预扣整窗资源。先完成的合法安全前缀保留，接受前失败和运行期中断分开报告。
- 错误使用稳定PartyError并经i18n显示，不直接显示内部异常字符串。`INTERNAL_FAILURE`锁存不可推进状态、保留诊断与最后验证边界，未完成段不得导出为有效录像；不吞错伪造wait。window-accepted/actor-intent-resolved/decision-requested/interrupted/finished等事件仅在所属事务安全提交后发布，消费者不能回调改世界。
- UI 草稿、焦点、ready、倒计时、预演均为 session；编辑不推进 tick/revision，不消耗双流或实体 ID、不写有效录像。已接受计划、游标、窗口进度、反应/打断锁存、待决 DTO 才进入机械状态。草稿须关联 baseRevision/控制归属；世界或控制权改变后重验并清就绪，不能静默提交过期输入。
- 单机保持同一个 `local:0` 人工槽。就绪按有活动成员的人工控制者槽去重，不按成员人数凑票。超时接缝使用可注入产品时钟；到期只生成一个确定批次，未交新计划的成员沿用已接受尾队列，无尾队列按 D-05 等待，不暗中托管。晚到、双击、取消与到期竞态最多接受一次；拒绝后不能无限自动重试。
- trigger 仅为事件链审计字段；相同规范化计划/W/startTick 在 manual、ready、deadline 等触发下机械结果一致。回放只读已接受批次，不读取墙钟/会话 ready。尚未开放的产品触发不得仅因 DTO 有枚举就直接暴露给玩家。

### 2.2 时间、打断与控制

- 一个客观 tick 时钟。每次增量取原生事件、actorActions、环境/居民边界及窗口剩余量的最小值；t=end 完成既有到期阶段和强制原子效果，不再领取新计划。跨窗动作余时只保存在原计时根，不能重复 prelude、状态尾声、扣时或环境块。
- 同 tick 成员领取按稳定 actorId，保留既有 NPC/阶段/客观块顺序；不为窗口重排经典怪物列表。多目标伤害完整发布后才打断，保留 P1a `a502cea` 实际受击者 scope 修复。
- 精细档显式记录 fineActorId；至多领取其一个动作并等待其结束，其他成员按自身计划参与。若其已有跨窗动作，只等该动作结束。安全上限1000 tick；达到上限保留续体，不补执行新动作。
- 人工空计划默认付自己的一个移动单位 wait；可配置取步前 interrupt。麻痹/沉眠走原生强制恢复，不消耗未执行计划游标。每同 tick 决策点最多一次失败/零耗时 intent，防零时间自旋；资源上限见 B3。
- 软打断覆盖新敌人、实际受伤、负状态新增/加重、低血线跨越、telegraph 覆盖；逐成员已见/低血/预警锁存按合同去重。开窗已见敌人不反复打断，同 tick 所有事实完整记录，展示顺序固定。默认 stop，可配置 continue；本步不接受 ai-this-window。
- 计划失效、确认/对话、楼梯/陷阱决策点、死亡、换层、无活动成员、终局全部硬停，优先于 continue。正常打断后下一次 advance 开新窗口预算；等待选择是原 seq 的下一 segment，不能借选择重置窗口预算。普通日志文案不是机械打断条件。
- 自动档只依据共享已知威胁/危险地形及上次打断，建议威胁时100、连续3个无威胁完整窗口后1000；不是自动连续提交开关。手动切档只作用于下次批次。quietWindows/automatic 入摘要，具体参数按 B3。
- 控制者/待切换者与 focus 分离。真实控制变更须录制，下一空闲决策点生效、不取消不可取消长动作；生效清旧队列，新控制者明确重交。P1b 不开放 AI 或远程槽，仅实现本步有消费者的授权/失效接口；不存无语义 AI 占位，不用切焦点模拟移交控制。

### 2.3 待决、持久化与预演

- 以 PendingDecision DTO 表示安全待决阶段，绑定 decisionId、actorId、intentOrdinal、worldRevision 与稳定 choiceId；存档/load/seek 能重建，拒绝旧选择和越权选择。确认“否”沿原生取消语义，不执行后缀；不序列化 generator/闭包，不默认点“是”。覆盖窗口白名单内所有可能确认/对话的动作；无法恢复的入口必须在开放前解决，不靠禁用原有能力冒称完成。
- 收据包含 seq/segment、起止 tick、原因、每步 ordinal/actor/intent/actionId/耗时/结果和确认选择。回放只执行输入一次，重算收据逐项核验；不把 trace 再当命令执行。保留现有 tick/level/双流/终局诊断与有效来源前缀。
- native/party/actorActions/extensions/world5/knowledge/random 各字段唯一归域；新增 Game 字段与惰性根登记 U03、recording-digest-contract、事务写集。控制状态不复制 HP、库存、阶段倒计时。每个窗口段末强制 full digest；事件 dirty 域逐段检查，full oracle 独立投影，涵盖所有活动/冻结成员与知识。
- 保留256命令 chunk、2048检查点、2待决 chunk 限额、接受前栅栏、旧 generation 隔离、乱序顺序发布、运输错误一次 inline 降级、完整性错禁止导出。段末 full 与临时导出末行 full 标记来源：续录只撤销临时末行，不能清语义段末/固定边界。确认、保存与 flush 不互等死锁；安全段可存，半个 resolver 不可存。
- OOS 报告保持“首个可验证分歧 + 区间”；能核验的 trace ordinal 与 dirty 事件可以定位，不能宣称所有 native/knowledge 隐错精确到某步。
- 预演使用独立 Worker 或隔离引擎容器，只复制已知世界投影、草稿和专用 RNG/allocator；不采用主局 snapshot→执行→load 的假隔离。未知格不可穿越，不运行隐藏敌人 AI；敌人按已知展示模型预测并标明不确定性。相同已知投影、不同隐藏世界应输出相同预演；主局日志、存储、确认、observer、双流/ID/前缀全部不变。结果带 baseRevision，过期丢弃，正式提交重新验证。
