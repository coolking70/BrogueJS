### 0.1 本文读过的原生事实（决定“膨胀往哪里放”）

| --- | --- |

### 0.3 模型边界（必须读）

v1 的 §9–10 数值来自一次性 Monte-Carlo 脚本（脚本放在会话临时目录，未入库；每预设 300 局 × D1–26）。它的“原生参照角色”是粗模型：武器基底均伤 `3.5(D≤2) / 8+0.4d`、净附魔 `0.3d`、护甲 `3+0.55d`、生命 `30+10×生命药水数(≈每4层1瓶)`；怪物参照为该深度可出现怪物（排除图腾/炮塔/守卫/召唤物/传说盟友）的等权均值；玩家按“生存×击杀速度几何均值”贪心换装，强化卷轴交替读在武器/护甲上。它只用于**确定量级与旋钮方向**，不是平衡证明。6B1 必须用真实生成器跑同口径的固定种子统计（§12 N-12），6Z 再以真实游玩校准。

## 1 物品等级（ilvl）与深度曲线

### 1.1 公式与来源加值（`ilvl.json`）

```text
ilvl = clamp(floor(depth × ilvlPerDepthBp / 10000) + sourceBonus + classBonus, 1, 99)
```

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `ilvlPerDepthBp` | 15000 | D1=1、D5=7、D10=15、D15=22、D20=30、D26=39、D30=45、D40=60 |
| `sourceBonus.floor / kill / vault / encounter / part / craft` | 0 / 0 / +3 / +5 / +2 / 0 | 与设计 §6.2 一致；part 首版不启用（L-D11=B） |
| `classBonus`（怪物分级，§5.1） | fodder 0 / standard 0 / elite +1 / champion +2 | champion = 带原生突变的怪；留给 L-D09 B 的冠军怪 |
| `siteIlvl` | 1 | 地表/无深度场景 |

## 7 强化卷轴与符文在 loot 下的映射（L-D03=A、L-D04=A）

### 7.1 强化卷轴 → 强化等级（`enhancement.json`）

| 戒指 | 每满 2 级本体附魔 +1 | 戒指键指数，必须减半 |

| --- | --- |

### 9.1 键的分类与上限（`caps.json`，loot 声明的 `clamp`，只在 loot 启用时收紧）

| 类 | 键 | loot 上限 | 理由 |
| --- | --- | --- | --- |
| **线性，自由膨胀** | `native.max-hp`、伤害平加、本地伤害%、`physical-damage-dealt` increased、抗性、寻宝、模块资源容量 | max-hp 9999；抗性 7500 bp；寻宝按预设 | 效果与数值成正比，可由怪物倍率直接抵消 |
| **指数，严格封顶** | `native.weapon-enchant` | loot 来源合计 ≤ +10 | 1.065^10 = 1.88×，同时作用命中、伤害、符文 |
| | `native.defense` | 最终 ≤ 220 内部（显示 22） | 怪物命中 ×0.987^防御；220 时命中系数 0.056，D26 怪物命中 ≈12.7% |
| | `native.regeneration` | 合计 ≤ 8 戒指点 | 8 点 ≈ 32 回合回满 |
| | `native.stealth-range` | 合计 ≤ 5 戒指点；原生下限 2 不变 | |
| | `native.transference` / `reaping` / `wisdom` / `light` / `clairvoyance` / `awareness` | ≤ 6 / 8 / 6 / 6 / 6 / 8 戒指点 | 转移 6 点 = 30% 吸血 |
| **乘法速度** | `native.attack-speed` more | ≥ −40%（最低 60 tick） | 底座硬限 25 tick 之上再收紧 |
| **减伤** | `physical-damage-taken`（loot 来源） | ≥ −50% | 新增的线性防御通道，替代护甲膨胀 |
| **命中** | `native.hit-chance` | 底座 500…9500 bp | 不变 |

核心思想：**Brogue 的指数键不膨胀，ARPG 的膨胀全部放在线性键上**——伤害（平加 + 本地%）、生命、减伤、抗性。这既满足“不向个位数妥协”，又不会把原生的命中/防御公式推到 5%/95% 两端。

### 9.3 怪物侧抗衡旋钮（按优先级）

1. **预设 `monsterScaling`（首版唯一启用）**：深度锚点 → 生命/伤害 increased。数值来源见 §6；调平衡时只改这张表，不改词缀。
2. `monsterAccuracyBp`：若将来放宽防御上限，用它抵消（现为 0）。
3. 掉率/稀有度权重：调“得到装备的速度”，不调单件强度。
4. L-D09 B 冠军怪（6B 之后）：局部尖峰，而不是全局倍率。
5. 不推荐：压低词缀数值或阶梯——这违背“接受膨胀”的方向。

目标带（模型口径：击杀速度 = 原生参照用的攻击次数 ÷ loot 玩家的攻击次数；生存 = loot 玩家能挨的击数 ÷ 原生参照能挨的击数；都已计入怪物倍率）：稀缺 ≈1.2–1.4× / 1.1–1.4×；**标准 ≈1.5–1.7× / 1.3–1.5×**；丰饶 ≈1.9–2.1× / 1.5–1.9×。即“刷得越多越爽，但怪物不至于被一击清场”。

### 10.3 手算示例：D10 标准预设，一只食人魔（elite）被击杀

1. ilvl = floor(10×1.5) + 1 = 16；解锁 T1–T3，阶权重 T3:T2:T1 = 25:40:35。
2. 掉率 3000 bp → `randomInt(1,10000)=1874` ≤ 3000，掉落；件数 `randomInt(1,2)=1`（预设上限 2）。
3. 类别 40/35/25 → 武器；基底 ilvl 12–26 段（轻 8、中 10、重 8）→ war_axe（1d6+11，即 12–17）。
4. 稀有度：普 700；魔 220×(1+150×16/10000)=272.8→272，×1.5（elite）=408；稀 70×1.4=98，×1.5=147；唯 10×1.4=14，×1.5=21 → 总 1276，稀有 11.5%。设掷中稀有。
5. 词缀数 3:4:5 = 45:35:20 → 3。依次：`keen` T3 掷 52%；`precise` T2 掷 15%；`brutal` T2 掷 +2/+4。
6. 腐化判定 600 bp：未中。稀有名两次抽取：“血鸦 / 之噬”。
7. 结果：“血鸦之噬 战斧”，伤害 (12+2 … 17+4) × 1.52 = 21–31；命中值 ×1.15。玩家力量 14（需求 19）时净附魔 −12.5：命中 ×0.455、伤害 ×0.455——**基底力量门槛仍是原生的强约束**，这件斧要配 `titan` 或力量药水才会好用。比较提示（设计 §10.1）应显示含力量惩罚后的已知差值。
