## 3 功能合同

### 3.1 新局默认联动与明确关闭

推荐B3-D1采用**发现式软推荐声明 + 通用新局选择解析器**。推荐关系属于包元数据，不在MainMenu/引擎中静态导入或特判loot/growth实现；与后续内容注册的强引用要求分开。

1. 用户开启loot或采用包含loot的预设时，若growth已安装且未在本次新局草稿中明确拒绝推荐，自动勾选growth，展示“随战利品推荐启用”及角色创建入口。已有growth选择不重复创建步骤或命令。
2. growth始终可取消。取消后loot保持开启，显示“已关闭推荐成长，使用无成长替代词缀”之类的本地化说明；不弹循环确认、不以watcher下一帧勾回。本次草稿内反复切loot、返回预设/创建页也尊重明确关闭；提供显式恢复推荐/重置草稿操作。推荐来源、手动选择和明确关闭在草稿中区分。
3. 关闭loot不连带关闭已选growth，避免撤销玩家独立选择；新一轮草稿按默认策略重建。推荐算法处理去重、稳定顺序及环形推荐，不无限展开；缺少可选推荐包时不报硬依赖错误，显示不可用原因且走fallback。
4. UI及提供“默认/推荐”语义的程序化新局入口共用解析器；显式传入精确模块集合的底层入口仍可表达loot单开和全关，不在`registry.manifest`、load或replay背后偷偷补growth。报告明确默认请求与显式集合的API边界。
5. 解析先完成最终模块集合，再建立创建计划。开启growth时必须有其创建步骤和恰一次合法 `create-character`；loot恰一次 `create`，三预设配置与payload一致。默认程序化中性角色与菜单显式身份选择沿现有合同，不默默替用户选择新职业。
6. 提交前校验整个初始批次，首层生成前确定预设、有效能力和目录；不得先按无growth目录生成再补开成长。创建、load、replay/seek重建顺序须明确：属性目录能力在角色创建前可查询，角色数值只在合法生命周期读取，避免“loot等growth角色、growth等建局”的初始化环。
7. 最终manifest只含真实启用模块与精确规则/配置身份；初始命令与之逐一匹配。缺命令、额外命令、重复create、配置矛盾或无效目录在退休活局前拒绝。关闭growth时不得保留其命令/创建草稿/状态；取消整个流程不改活局、双RNG或录像。

### 3.2 正式可选属性能力

`growth.public-character.v1`保持原有窄查询，不扩成跨模块私有状态后门。新增 `growth.attributes.v1` 推荐定义为**公开属性目录能力**，不返回任意actor的属性值：

- 输入精确 `{v:1}`；输出版本、规范排序的属性目录及机械fingerprint。每条至少明确稳定属性ID、正式Stat键、名称/说明引用、单位、合法有效值界限与是否可供装备加值。由真实已注册、可被下游消费的键形成目录，不以安装名推定能力。
- 以当前 `growth.attribute.agility` 等定义ID为稳定真相。推荐 `<id>`使用完整定义ID，显式给出 `definitionId → growth.attribute:<id> → loot展开ID` 的一一映射；不从末段猜ID，不将历史纯包夹具的strength/dexterity/wisdom当真实growth目录。若选短公开ID，必须冻结显式无碰撞映射并纳入身份，不能隐式别名。
- 当前Stat键语法缺口须用**受限的正式Stat键语法/适配**解决，只有合法已声明属性引用可通过；不全局放宽 `validId`、sourceId、模块ID和任意冒号字符串，不修改测试守卫来接受非法输入。能力中给出的键须能由 `foundation.stats.v1` 和真实 `StatQuery`查询。
- 能力缺席/未启用、受支持的空目录与不支持输入版本分别定义；非法声明、重复ID、缺引用、错owner、错误返回形状/指纹不能伪装成正常缺席。UI读口不暴露NPC、奖励账本、原始组件或活体引用。
- loot通过公开能力和实际Stat声明构造availability：adept只展开可用属性；sage/focus、scholar/xp按各自真实键独立启用，不把“属性列表非空”当全部能力的替身。未启用/未安装growth时保持 **sage→mending、adept→titan、scholar→omit** 与既有权重合并语义。
- 能力集合、映射和属性规则进入有效目录/运行身份，建局一次确定；升级和加点只改值，不改变目录身份或重掷既有物品。load/replay验证当时精确身份，不用当前默认目录静默重释旧物品。

### 3.3 属性来源、无环DAG与资源物化

先交“配置定义 → 原始构筑/等级 → 属性键 → 下游键/公式 → 单位/舍入/上限 → 来源 → 提交点”表，逐项与当前数据核对。保持现有数学，以下为默认样例与当前接点，不是重新调参授权：

| 输入 | 应接的现有语义 |
| --- | --- |
| 等级 | 按已有表发属性/技能点，偶数等级自动生命；等级不额外增加命中、伤害或等级压制 |
| strength-training | 训练成本3属性点/级、训练上限4；每级贡献力量，进入 `native.strength`，继续影响原装备需求/附魔公式；不再加一层力量百分比伤害 |
| agility | 攻方每点+100bp、守方−50bp概率修正，经 `native.hit-chance` / `native.evasion`；潜行为现有floor规则。不得把它直接加到 `native.accuracy`当成等价命中百分点；原必中/必失及取骰优先级保留 |
| constitution | 每点最大生命+3，经 `native.max-hp`；自动生命、药水、直接loot生命与属性派生各计一次 |
| will / perception | 意志按现有规则影响专注/冷却；感知影响手动/自动搜索输入。沿已有floor/比例下限/预算，不新增法杖收益或视野效果 |
| 可选combat | 已有体质→体力、意志→韧性映射读取统一有效属性；combat缺键仍跳过，不制造虚假声明 |
| 身份、被动、临时效果 | 复用有限效果词汇、预算与作用域；明确即时读取和施放快照边界，不将应冻结的效果随之后换装追溯改值 |

**求值结构**必须单向：

```text
等级 / 永久分配 / 身份与继承构筑       装备 / 允许的属性修正
                 \                    /
                  有效 growth.attribute:<id>
                           |
              已声明属性规则、技能/身份效果求值
                           |
       native / growth / 可选combat派生键与原生公式
                           |
               安全点物化 + 已知来源投影
```

- 永久分配值、已付费点和初始/身份/继承来源保留在growth组件；装备只贡献临时有效值，不能写回values/allocated、退还成点数或在卸装后永久留下。永久投资cap/totalCap与有效属性cap分开定义（见B3-D3），保持默认配置规则及已存在上限，不借接线放大预算。
- 推荐底座提供有限、声明式的分阶段派生输入，按受限拓扑求值；不是允许provider在collect里调用 `stats.value`。安装/组装时验证无环、缺键、重复所有者和越层依赖；阻止属性↔原生力量、属性↔容量等回边。动态属性数须有明确预算，不能取消原行数限制。
- 同一求值上下文冻结actor/target、装备、知识与效果快照；源收集和派生消费不能依赖模块注册顺序。中间值沿现有精确整数/有理数、预算、舍入和最终clamp，不把原始来源简单相加充当最终结果。
- 删除旧的重复贡献路径，保留单一物化账本；不把已加成长的力量/maxHp再当基础。升级/分配恢复按当前配置，默认不补当前生命/专注、不清冷却；装备造成的容量增加不补满、降低只按原合同钳制。装备经属性间接增加生命也不能冒用growth永久 `refill-delta` 权限刷治疗。
- 创建满血、原生药水、洗点、变形、克隆/分裂、复活及load重建保持当前所有者语义；对触达路径作定向回归，禁止在查询中修档或再次赠点/补血。玩家与NPC共用属性规则，不能让未授权UI凭actorId读取未知NPC。
- 技能学习/树解锁推荐以永久构筑值检查，装备有效值用于机械收益；不引入卸装即遗忘技能、临时装备刷解锁或隐式自我满足前置。施技快照需要有效属性的路径须显式接通并验证；确需改变旧前置语义在B3-0列差量，不暗改。

### 3.4 缓存、知识与来源显示

1. 提供失效表：创建、升级/加点/洗点、身份/技能装配、临时效果施加/到期/消费、装备更换/原生强化/否定、药水与基础形态、load/seek/换局。每项列机械revision、已知投影、物化和录像摘要的实际责任；不能只新增一个UI刷新计数。
2. 机械值、knownOnly值、装备hypothetical及加点组件预览必须共用DAG和映射。**先过滤未知来源再计算所有下游节点**，不能先用真实有效敏捷/体质算出命中/HP，再只隐藏来源行；也不能经差值或剩余额度反推隐藏词缀。
3. knownOnly/hypothetical只使用局部memo，不污染活局缓存或物化账本；知识变化刷新已知来源及相关摘要，纯知识变化不增加机械值。读档/seek重建绑定与缓存，旧会话、草稿和闭包释放；查询不触发reconcile写状态、揭示或RNG。
4. 来源至少能区分等级自动收益、永久分配、身份/模板公开来源、技能/临时效果、具体装备槽/物品；稳定sourceId不以数组顺序冒充身份。派生结果可追溯“体质来源→最大生命规则”，共享上限、舍入与条件单列，避免把每件独立边际收益相加冒充总收益。
5. 装备来源页、详情/四槽比较、角色属性页及加点预览显示相同已知口径：永久值、已知外部增量、有效值或不确定提示、规则单位/上限。敏捷命中修正与命中值/对目标命中率分清；全部文案/i18n引用来自公开目录，不给Vue传raw组件/moduleData再靠隐藏元素遮挡。
6. **本步新激活的非符文growth词缀须闭环**：sage、adept、scholar分别列能力、真实机械效果、来源、触发事实、零收益/封顶/负例、知识缓存。接6B2实际装备容量/属性提交及真实XP奖励等安全点，只揭示匹配行，重复幂等；纯查询/load重建/重复reconcile不能揭示。XP未获收益或未实际参与的处置先明确。此项不属于后移6B4的符文触发协议，不能全部借符文延期。

### 3.5 职业、天赋/流派树的数据扩展框架

只交接口和最小见证，保留现有样例内容与创建体验。推荐生产外部注册为空，测试中注册一个无叙事含义的最小贡献包，证明真实接线。

1. **公开注册入口**：在通用模块声明/目录组装层增加受校验的可选贡献，形状至少有schema、owner、版本/机械指纹，以及职业、树/节点、属性规则集合；具体字段在B3-0冻结。包发现不得静态导入另一模块私有文件。贡献者只能注册自有命名空间数据，不能覆盖growth原定义、替换全局回调或写growth组件。
2. **两阶段汇总**：先收集本局启用模块的纯JSON声明，再由growth领域适配器验证/冻结有效目录；前置于属性能力发布、loot目录准备和世界生成。校验owner/ID唯一、跨包引用、属性/技能/标签存在、前置无环、预算与非法效果；稳定排序，不以import/安装顺序决定覆盖或收益。
3. **职业**：复用既有Identity的初值/选择预算、赠技、推荐、有限effects；创建仍经 `create-character`，不加具体职业分支。强引用growth的内容包若未启用growth，应在新局计划预检明确拒绝或按预先声明的惰性策略禁用；推荐选择明确拒绝无效内容配置。这与loot可独立运行的软联动不同，不能拖累无此内容包的其它模块。
4. **树与节点**：定义稳定tree/node ID、名称、所属/可见条件、前置边和对现有技能/属性规则的引用；推荐作为现有学习/前置系统的数据组织层，复用技能点/费用/已学状态。树框架不另造天赋货币、树专属持久镜像或新的数值内容；UI可先用通用列表，不要求画布树。
5. **属性规则**：只允许现有常数/等级/属性幅度与有限端口、预算、槽、条件词汇；规则依赖进入§3.3的受限DAG。禁止eval、字符串函数名、任意对象路径和来源反查写入；新原语超出本步时列具体缺口，不写空成功接口。
6. **生命周期和身份**：本局注册集合不可热变；目录指纹包含贡献者版本、规则、稳定映射和引用，排除locale展示文本。缺包/不同目录严格拒档且保活局；同版本保存、回放、seek不重新赠技/发点。默认空注册不得改变已有职业样例/收益。
7. **最小见证与接入说明**：给“声明贡献→发现→组装校验→菜单/角色读模型→合法创建/学习→属性来源→保存/重播”的精简示例。只需一个测试职业引用现有技能和一个最小前置关系/属性规则，或空生产注册配等价测试fixture；不能只导出未被消费的TypeScript类型便称框架完成。fixture/调试入口不进生产包。
