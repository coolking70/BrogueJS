## 范围
1. **冻结 C5-1 合同**：把设计中 5A 的接口（LevelRef/层身份与所有权、simulationTicks 与在场/离场两种精度、受控世界事务、离线结算 planner/事务、物品/容器/资源点/工作票据、结构层与房间识别原语、RestPoint 通用休息）写成精确的 TS 类型草案与行为合同文档 `docs/ext/phase5a-contract.md`：每个导出名、字段、不变量、错误码、事务边界、版本号（foundation 5→6 的计划，阶段 5 内由 5A1 首次落地时分配；giants/combat 等现有模块不受影响）。5B（crafting，dot 开发）需要的 SDK 子集单独成节，作为日后派发给 dot 的契约。
2. **体积探针**（P5-D12=A 前置）：在仓库外脚本或 `scripts/` 下的只读探针中，用现有真实 Game 构造“长期建设”量级的状态（例如 8 个营地层 × 24×20 结构格 × 16 居民、若干容器与票据的模拟数据，按设计 §12.2 预算），测算当前完整 checkpoint 录像与存档的体积/序列化耗时；给出“摘要+周期快照”新版录像格式的设计（字段、周期、校验、seek 行为、与现有 version 的关系），只写设计与探针结果，不改录像实现。
3. **核对现状事实**：确认收尾后的基线版本号（foundation=5、各模块版本）、楼层缓存/持久化现状、物品系统可扩展点、地形写入与 cellProperties 现状，在合同文档中记录引用的文件/函数。
4. 给出 5A1 / 5A2 / 5A3 的任务拆分建议（每步范围、验收、门禁、预计触碰的共享文件），以及 5B 派发给 dot 的完整任务包草稿（含固定产品选择：手采 100 tick/1 单位、stack 99、三类工作台、固定普通材料/+0 已知简单装备/口粮/床箱台套件、单包 ≤128 配方，以及数值表草案供维护者批准）。
