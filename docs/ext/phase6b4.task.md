## 2 目标、范围与非目标

**目标**：玩家在真实游戏中用强化卷轴提升 loot 装备，满级后按规则精炼；自然掉落可产生随机符文，固定/随机符文按管线强度执行，首次真实效果提交后只揭示对应行。完整链在同版本存读、录像、seek、续录中一致，新增功能通过 P0 门禁且不显著拉高全模块基准。

实施范围：loot 模块及自有数据/locale/UI/测试；宿主原生读卷轴与目标选择、受控物品计划/事务、必要的符文强度和结算事实端口；growth itemGrowth 适配只走公开合同。共享底座改动逐项说明必要性、权限、写集、失效与测试，不能私引其它模块或授予任意 Item 写权。

非目标：

- 不调平衡曲线、成本供给、词缀阶值、唯一收据或预设哲学；不补职业/流派内容，不重做成长属性系统。
- 不做 6C 套装、插槽、符文之语、工位重铸、crafting 联动或 part/craft/site 新来源；T7、套装与符文之语继续关闭。
- 不扩槽位、背包、随机符文可用装备类别；戒指不发武/甲符文，非 loot 投掷物维持当前行为；不恢复 venom/vampirism/vitality 生成。
- 不做 CE 对照、旧开发档兼容/迁移、全项目测试/组合矩阵、全面性能重构、Worker/WASM、新依赖或美术；不自动 commit/push、合 main、打标签、发布或开 6C。

## 3 功能与安全合同

### 3.1 强化卷轴与精炼

1. **单一入口**：保留读强化卷轴→选真实背包目标→提交→自亮/解咒/回合收尾。UI 经 `executeCommand` / `executeItemCommand`，不得直接调用状态写函数。详情按钮若提供捷径，也必须使用同一卷轴和选择流程，不新增免费强化或碎片强化。
2. **保留已落盘参数**：普通/魔法/稀有/唯一上限 10/8/6/4；武器每级本地伤害 +1000bp，每满 3 级增加 1 附魔当量（管线 quarter 单位×4）；护甲每级 +5 最大生命、+5 内部防御；戒指每满 2 级本体附魔 +1。沿当前本地 flat→increased→floor 与最终 cap，只贡献一次；戒指原生 implicit 已承载时不再另加。生命升容不补、降容钳制保持。
3. **原生字段**：loot 武/甲强化不再 +1 原生 enchantment、不降低力量需求；以 enhancement 唯一持久值派生收益。戒指同步既有 implicit/唯一覆盖加 floor(enhancement/2)，保留未知戒指实际有效值的现行规则。非 loot 装备、法杖/魔杖/护符及投掷物仍走当前原生路径；模块关/缺席不改变该路径。
4. **满级精炼**：只选本件正面数值行，在原阶/唯一固定行原 ranges 内重掷，逐分量取新旧较大值；不换行、不升阶、不改目标类、负面/腐化历史/唯一身份。多分量行冻结顺序，固定区间不额外取骰；无正面数值候选或全部达上限拒绝。候选是否包含部分已满行、无提升仍消耗及未知行反馈由 B4-D1 冻结，不能在实现时悄悄改变掉骰语义。
5. **消耗必须原子**：先核实卷轴、目标所有权/数量、当前 revision、上限/可精炼性与 growth 计划，再消费。原流程可能在选目标前消耗卷轴，必须审计 pending 状态：对新“满级不可精炼”拒绝实现从读卷轴起零成本，不能只让选择函数返回 false 而卷轴已丢失。取消/陈旧/非法/失败不扣物品、不增加 timesEnchanted、不留 growth 收据、不推进机械时间或实质 RNG；成功只消费一张，按原动作耗时推进一次世界。
6. **完成副作用**：成功沿当前自亮、解咒、穿甲状态与鉴定尾处理。`corrupted=true` 不等于当前仍诅咒；解咒后负面词缀保留，合法存档不能套出生等式拒绝。满级全满且仍诅咒的优先级采用 B4-D1 裁定。`timesEnchanted` 增量与精炼计数单列，避免无意抬高未知戒指收益；纯知识变化不额外增加机械收益。
7. **growth itemGrowth**：通过宿主通用目标适配，把最终 `destination: enchantment` 输出授予 loot enhancement；growth 不认识 loot 私有数据。必须覆盖 preserve/replace、0/1/多级、perItemCap/runCap、跨装备上限、满级精炼及替换成属性点/技能点等合法配置。冻结“请求量/实际接受量/收据量/timesEnchanted量”表，拒绝时两边均不提交。B4-D2 决定溢出和精炼换算，不乘以 magnitude 无界循环。
8. **否定与生命周期**：建立强化/符文在否定、鉴定、解咒、卸装、丢弃/拾取、换层、load/seek 后的字段与缓存表。否定后不能由 collect/重建重新长出已移除符文；不能把创建时的 runicType/enchantment 等式强加于所有合法后续状态。具体沿现有否定语义，无法表达的持久状态在 B4-0 明列并升版本。

### 3.2 符文强度与随机生成

**强度所有权**：runicType/原生旗标继续控制是否执行；loot 符文行给 `native.runic-power` / `native.armor-runic-power` 的该件 L0，非 loot 沿当前净附魔。现有键用 quarter enchant，数据 runic-strength 用整当量，必须明确 ×4/÷4 只一次。不得写成“原生净附魔 + loot 强度”、不得让另一件装备的符文覆盖本件、不得绕过来源预算/最终 clamp。其他合法修正沿管线顺序作用，knownOnly 不泄露未知 L0。

冻结读取点表，至少包括：近战概率、武器效果时长/数量/击退距离、护甲吸收/反伤/分身、射线反射、实际适用的投掷与受控攻击、详情和假设比较。`Combat.ts`、`Game.ts`、`BoltReflection.ts`、`NativeStatSources.ts`、`ItemDetailEquipment.ts` 是当前审计入口，不是完整白名单。保持当前效果函数与概率曲线；固定强度只替代输入，slaying/immunity 等强度无机械作用者不能虚报收益。

| 符文集合 | 生成及执行边界 |
| --- | --- |
| 武器正面 8 条 | speed、quietus、paralyzing、multiplicity、slowing、confusion、force、slaying；quietus 最高 T4，paralyzing 最高 T5，其余 T6 |
| 护甲正面 8 条 | multiplicity、mutuality、absorption、reprisal、immunity、reflection、respiration、dampening；最高 T6 |
| 负面 5 条 | 武 mercy/plenty，甲 burden/vulnerability/immolation；只来自既有腐化负面选择/回退，不进普通正面池，沿固定行为 |
| 强度 | T1–T6 为 2、3、4、5–6、7–8、9–10；固定唯一行沿 §1.2，不套随机阶上限降值 |

- 保留当前数据中的具体权重，不按历史“组权重300”再次乘算或归一化调参。符文为后缀、共享 `rune` 互斥组，每件最多一条；不得与固定唯一行再叠随机符文。正常词缀数/前后缀预算、腐化追加与补偿规则保持；补偿不得越过该符文自身 maxTier。
- 打开族前，补齐 `AffixesFile`、schema、有效目录、`validateLootItem`、生成器、原生固定装配、知识 DTO、codec 的一致合同。非法双符文、武甲错配、阶/值越界、目标类缺失或不适用、native/模块不一致、畸形 JSON 均受现行严格校验；不放宽原预算。
- slaying/immunity 的合法目标类来自宿主有限稳定目录，不按屏幕所见怪物、当前世界扫描结果或 locale 排序抽取。B4-D3 冻结稳定 ID、权重/顺序、持久 owner 与 `vorpalEnemy` 映射；仅这两种符文取目标骰。未知目标不进入已知 DTO；名称本地化，不传隐藏类别让组件自行隐藏。
- 在原生成顺序上登记新增目标类骰、腐化补偿重掷与精炼各自的候选顺序、空候选、单候选和固定区间规则。保留每件 ≤64 次随机调用上限；增加固定向量和上界负例，不用均值代替顺序检查。部分落地/无落点跳过沿现有消费规则，异常回滚双流、ID、唯一收据与完整世界。

### 3.3 首次触发协议：25 条符文行逐项闭环

交付 **21 条定义 + 4 条固定唯一行** 的账本，每行列：itemId/稳定 rowId、runicType、目标条件、强度读取、真实执行点、事实字段、揭示条件、负例及测试入口。非符文 D5 和 6B3 三条成长揭示保留，不借符文任务重新实现。

推荐 B4-D4：以**实际效果提交**为揭示点，不以“参与抽概率”“拥有符文”“发生一次攻击”或显示查询替代。需要明确处理：

| 分组 | 正例与必须区分的负例 |
| --- | --- |
| 概率武器/控制/力场/分身 | 对应效果真实提交；未中、骰失败、免疫/无有效目标、召唤无落点、击退完全未发生、重复回执不能误揭示 |
| slaying/immunity | 正确目标类上的实际斩杀/伤害阻断；不匹配、普通击杀、别的免疫来源不能归给该物品 |
| 吸收/反伤/分摊/反射 | 实际吸收/反伤/分摊/改变射线的回执；0伤害、反伤无对象、别的反射来源不能冒领 |
| respiration/dampening 等常驻保护 | 有对应危险且实际阻止效果；安全地面待机、仅装备、查抗性/视野不算触发 |
| 负面符文 | 实际治疗/复制/加重负担/额外承伤/自燃等效果；对玩家有害也可揭示，零变化与被后续失败回滚的事件不算 |

对“效果成功但没有数值变化”、原生原本会揭示但 loot 规则不应揭示等冲突，B4-0 逐行裁定，不能用统一 hpLost>0 条件漏掉反射/免疫/负面符文，也不能仅见 runicKnown 就全揭示整件。

协议要求：

- 宿主产生脱离活体的可信事实，至少能绑定结算 ID、actor/target、itemId、符文种类、来源行/阶段与实际结果；模块纯计算揭示提案，宿主重新验证来源及当前绑定后原子提交。仅新揭示时失效已知缓存/摘要；重复幂等，不额外抽实质 RNG。
- `runicKnown`、原生实例/种类知识与 loot 行 known 明确同步表：正常首次只揭示匹配行/允许的原生符文信息，不连带其它词缀或唯一专名；完整鉴定/熟悉度仍沿既有全揭示。原生自带揭示分支须纳入同一同步边界。
- 事实与原效果共用事务。后续效果、知识 validator、消息/物化提交异常，恢复完整对象图、绑定、双流、ID、知识、摘要及 growth 收据；禁止先发布知识再回滚战斗。
- 不在 collect、stats.value、hypothetical、详情、渲染、load 重建、重复 reconcile 内触发。跨层/seek/换局后旧事实不可写新物品；可选 combat/giants 只用公开端口，必要路径有限取样，不增加组合矩阵。

### 3.4 UI、已知信息与缓存

在现有背包/战利品面板提供强化等级/上限、下一次是强化还是精炼、合法卷轴入口与拒绝原因；不可精炼时有可信提示，未知行不能为预览而泄露词缀/值/目标类。精炼按 B4-D1 显示“有可能无提升”等事实，不承诺必升。

强化后实际属性、详情、四槽比较与来源行一致；符文显示名称、已知强度、目标条件和实际适用的效果，条件与概率不合并为无条件 DPS。删除“6B4 尚未接线”占位前须有真实证据。已知预览沿 `hypothetical(..., true)`，不再沿原生 +1/减需求推算 loot 下一次收益；无提升/封顶/无强度收益有明确文案。

保留双戒真实槽位规则、未知分解区间、native↔loot 混合比较、加载外壳与创建模态修复。刷新覆盖强化/精炼、揭示、否定、卸装、load/replay/seek/换局；忙碌提交只发一次，取消/关闭/失败不重试已提交动作。全部玩家文本走 i18n，所有 DTO 先过滤知识再交组件。
