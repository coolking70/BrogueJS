# S2 — Gunplay Vertical Slice

在 `product/shooter-prototype` 分支执行 `npm ci`、`npm run dev`，打开 `/shooter.html`。生产构建执行 `npm run build`；原 `/` 产品入口继续独立存在。此分支未发布到公开试玩地址。

本阶段按 Shooter Runtime RFC 的 S2 实现一张枪械测试场。S1 基线为 `1e0d54f38010ae2dadf5de9e0e56202c22854162`，不自动追合 `ext/phase4` 或 `main`。

## 试玩

| 设备 | 移动 | 瞄准与开火 | 换弹 / 切枪 |
|---|---|---|---|
| 键鼠 | WASD / 方向键 | 鼠标瞄准，左键射击 | R / 1–4 |
| 标准手柄 | 左摇杆 | 右摇杆瞄准，RT 射击 | X / Y 循环切换 |
| 触屏 | 左摇杆 | 右摇杆拖动瞄准并射击 | 屏幕按钮 / 武器栏 |

手枪、霰弹枪、榴弹是半自动，每次按下扳机只射一发；触屏需松开右摇杆再拖动。步枪可持续按住开火。运动、瞄准与换弹可同时进行。松开输入后停止；切出窗口或后台会暂停并清空输入。

换弹使用无限练习备弹。射击恢复期间按 R 会保留一个换弹请求，冷却结束后执行；切枪会清除该请求并中断正在进行的换弹，未完成的弹匣不增加子弹。切枪不会绕过当前射击冷却；半自动武器切换后仍须重新扣扳机。

六只基础敌人使用简单追击、圆形碰撞和近身攻击；敌人 70 HP，玩家 100 HP，接触攻击为每 30 Tick 最多 8 伤害。倒下后等待 90 Tick，在出生点无阻挡时重生。玩家出生点被占用时按固定顺序查找附近备用位置，避免倒下后敌人冻结而无法重生；敌人的出生点被占用时继续等待。没有尸潮导航或生成导演。

榴弹爆炸会伤到自己，墙体遮挡爆炸。浅水减速；火、气仍只显示接触 Tick，没有接入完整环境伤害或传播。

## 武器数据

30 Hz 机械时钟；距离使用每格 1024 World Unit。

| 武器 | 扳机 / 弹道 | 射击间隔 | 弹匣 | 换弹 | 伤害 / 射程 |
|---|---|---:|---:|---:|---|
| 手枪 | semi / hitscan | 9 Tick | 12 | 36 Tick | 32 / 24 格 |
| 突击步枪 | auto / hitscan | 3 Tick | 30 | 60 Tick | 15 / 28 格 |
| 霰弹枪 | semi / 8 pellet hitscan | 24 Tick | 6 | 72 Tick | 每 pellet 14 / 11 格 |
| 榴弹 | semi / mechanical projectile | 24 Tick | 3 | 90 Tick | 中心最高 95，径向衰减；半径 1900 WU |

榴弹速度为每 Tick 480 WU，命中或 36 个飞行 Tick 后爆炸；发射当 Tick 尚未消耗飞行时间。普通枪弹瞬间判定，tracer 只是短暂表现。每支枪有独立散布、移动散布、后坐累积和恢复参数，均位于模块机械数据包。

S2 只实现 semi/auto 和 hitscan/projectile。burst、charge、beam 不接受为可执行规则，不提供空壳实现。

## 结构与所有权

- `src/ext/modules/firearms/`：独立 `firearms` ID、版本 `1.0.0`、机械 JSON 指纹、规则、状态、弹道、模块文本与自有测试。不依赖 combat、growth、giants、narrative。
- `src/ext/realtimeCatalog.ts`：单独发现纯实时模块入口，避免 headless Shooter 导入旧 Game / i18n 机械路径。旧扩展 catalog 识别实时 descriptor，但不把 firearms 伪装成回合制开关。
- `src/engine/Combat/DamageResolution.ts`：共享伤害 authority。准备只读，提交凭据限同实例、单次使用，目标或来源 revision 改变后拒绝陈旧提交；HP 不暴露给模块写入。开放 kinetic/explosive/fire/electric/toxic 类型，本阶段枪械只使用前两类。
- `src/engine/Movement/`：固定 Q16 正弦表、最长 65536 WU 的分段整数 trace、嵌入起点立即碰撞；移动仍复用 S1 sweep/slide 和派生空间哈希。
- 生产 `ActorActionScheduler` 负责枪械冷却、换弹的整数时钟，模块不使用浏览器计时器。
- `ShooterSession` 负责记录事务、空间与生命状态、简单敌人、环境接触以及模块生命周期；模块通过窄只读世界查询、伤害请求和表现事件接入。

每个 pellet 的散布来自 runSeed、actorId、weaponInstanceId、shotSequence、pelletIndex 的局部整数混合，不消费旧全局 RNG。机械角度为 0–4095；浏览器浮点输入在适配器结束，正弦和余弦的机械取值由已提交 Q16 表确定。

目前伤害目标仅为 entity；部位 / group 策略、Boss 与原生 Creature 伤害路径尚未接入实时产品。

## 输入、存档与录像

连续输入保持五字段 `InputFrame`，位 1 表示开火；reload/equip 使用独立的有序 `WeaponCommand` 流，在同一个 Tick 事务中执行。非法帧与命令在修改状态前拒绝。失焦、暂停、重开和读取清理尚未录入的浏览器输入。

格式为 `broguejs-shooter-s2` / `broguejs-shooter-s2-replay`，版本 3。S0/S1 档明确拒绝，不迁移。

完整状态包括精确位置、移动余量、地形接触、生命值与伤害 revision、重生/攻击时钟、统计、模块精确版本/规则指纹、各武器弹药/射击序号/后坐、扳机与待换弹状态、动作调度器，以及所有飞行榴弹。UI 投影由状态重建并校验，空间缓存重建；表现事件有有界保留窗口。

录像从初始检查点重演所有帧和命令，再逐字段比较完整最终状态；这不是密码学防篡改，机械结果等价的空操作历史可以等价重放。读取建立新 Session，失败不会替换当前 Session。录像导入上限 20 MiB，最长记录 108000 Tick；一次追帧也不会跨过记录上限。

“运行诊断与重开”可选择下一次重开的实时模块集合。本阶段支持 firearms 或空集合；空集合保留移动、空间、存读档和录像，敌人不发动攻击。物理删除 firearms 目录后，这个空集合路径与原产品仍应构建、运行。

## 验收与边界

可复现专项：`node scripts/check-shooter-s2.mjs --output <仓库外目录>`。可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已有 Chromium。`--engine-only` 与 `--browser-only` 均明确标记未执行部分，不能替代完整证据。

`check-module-composition-smoke.mjs` 在原真实 Game 子集之外，增加实时产品子集的新局、游玩、checkpoint、replay、检查点续录、构建 UI 和缺失模块拒绝。两种产品各按自己的运行时模块集合验证，不声称回合制模块已实时化。

性能与全部实际结果见 [S2-report.md](S2-report.md)。鼠标、触屏和手柄的主观手感仍须维护者在真实设备上完成至少 5 分钟试玩。S2 Go/No-Go 未经实机验收，不据自动化结果直接进入 S3。此阶段没有 Horde、Mission、Support、Meta 或 Multiplayer。
