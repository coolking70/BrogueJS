# UX-1E 渲染与视野采样

日期：2026-09-29。原版：`http://127.0.0.1:5394`（未改的 `playtest-remediation` 工作树）；开发版：`http://127.0.0.1:5393`（`playtest-fixes` 工作树）。可重复脚本为 `node scripts/ux-1-render-profile.mjs`，原始 JSON 在 `/tmp/broguejs-ux1-render-profile.json`，不入仓库。

每版用种子 27027、33008 各开一局。D1 是正常新局；随后逐层调用原 `generateDepth` 生成 D2–D5，再在 D1/D3/D4/D5 各执行 6 个真实 `wait/move` 命令，共 48 命令/版。**这些是自然生成的楼层，但进入楼层是合成转换，不是自然长局**。为避免战斗死亡干扰，将每层玩家 HP 临时设为 10000；仍保留自然生成的怪物、地形与行动。采样前清除待确认消息，以免输入因展示暂停被吞。

通过页面运行时包装 `updateVision` 与 `onRenderRequested`，记录每命令调用次数和耗时；命令到下次 `requestAnimationFrame` 回调作为输入到下一帧的代理指标。前后检查点比较地图地形、玩家、怪物、回合/时钟与完整 RNG 状态；8 个深度检查点原版和开发版全部相同。包装只读计时，不改变调用顺序；开发版没有针对渲染或规则做性能修改。

| 指标（48 命令/版） | 原版 p50 / p95 / max | 开发版 p50 / p95 / max |
|---|---:|---:|
| 命令耗时 ms | 4.7 / 14.8 / 81.8 | 4.5 / 12.4 / 90.4 |
| 命令至下次 RAF ms | 15.3 / 22.5 / 88.7 | 14.5 / 22.4 / 99.2 |
| `updateVision` 合计耗时 ms/命令 | 1.8 / 3.0 / 5.2 | 1.8 / 2.9 / 3.5 |
| `onRenderRequested` 合计耗时 ms/命令 | 0.9 / 2.1 / 5.4 | 1.0 / 2.2 / 5.9 |
| 总调用 | vision 143、render 49 | vision 143、render 49 |

每条常规命令只有一次 `onRenderRequested`；种子 27027 的 D4 一条 `move` 有两次，且未增加回合（下一条动作继续推进）。同种子的 D4 存在约 82–90ms 命令尾部值，两版均复现；其 `updateVision` 与 render 合计约 3–4ms，不能将这次卡顿归因于渲染。`updateVision` 通常每命令约三次，但它承担规则可见性与光照更新，本轮不删减。

因此本轮**未做渲染合并或视野优化**：49 次 render/48 命令没有显著重复，强行合并会改变即时视觉反馈与装饰 RNG 时序而缺乏收益证据。此结论限于上述两种子、四层和短命令段；尚未复现用户所说的自然 D4 长局偶发卡顿，也未覆盖复杂火焰/气体场景。`requestAnimationFrame` 数值是绘制前回调时间，不是最终屏幕呈现时间；Pixi ticker 内直接调用的动画 render 不计入 `onRenderRequested` 包装。更深的卡顿归因需结合主线程其它热点采样及自然长局轨迹。
