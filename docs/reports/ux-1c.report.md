# UX-1C 桌面交互、缩放与布局整改报告

日期：2026-09-29。工作树：`codex/playtest-fixes`。本单元只改显示与输入手势，不改游戏规则、存档或录像字段。

## 复现与原因

- 新增 `ux_1c_display.test.ts` 红测：桌面底图每格不小于 12px 时 `computeMapCamera(..., zoom=1.5)` 仍返回 `follow=false`。实测 4 项中 3 项通过、该项失败；原 `zoom=1` 布局断言通过。原因是原相机在可读性阈值处提前返回。App 当时仅紧凑布局挂地图缩放控件，且控件仅在跟随状态下出现。
- `GameCanvas` 鼠标移动只更新引擎悬停文字，地图绘制从不读取该格；CE `IO.c:655-702` 的光标模式会高亮格子并同步位置说明。这里借鉴其可见反馈，不宣称 CE 的被动鼠标悬停与 Web 相同。
- `AgentControls` 在细指针桌面被 App 传入 `hideControls=false`，故左下虚拟方向键虽只有 0.15 透明度仍显示。浏览器放大时紧凑视口条件又会显示 DPad。
- `Sidebar` 固定 `100vh`，根布局使用 `100dvh` 和隐藏溢出；上方块增高时日志可被压缩。此为源码确认的布局风险，具体用户环境裁切形态留给浏览器验收。
- 完整 `?` 命令帮助原已存在，侧栏没有可点击入口和就地键位提示。

## 改动

- `mapCamera.ts`：桌面默认 `zoom=1` 维持整图的等比/拉伸布局，主动放大才按玩家位置进入可平移视图；`autoFollow` 使 1280×720 等窄桌面仍维持整图默认布局，紧凑视口保留自动跟随。新增显式适配全图状态、回中与缩放边界处理。现有 FE-1 的默认桌面断言未修改。
- `GameCanvas.vue` / `mapPointer.ts`：画布滚轮只改地图缩放，Ctrl/Cmd+滚轮交给浏览器；在放大视图内左键拖动平移，超过 5px 才认定拖动并抑制随后的格子点击。命中仍通过 Pixi `toLocal` 逆变换。鼠标悬停对已可见、记忆或魔法测绘的格子绘制淡底与描边；未知格不画。离开画布及进入背包/目标/帮助模式时清除或隐藏。
- `MapZoomControls.vue`：始终提供放大、缩小、适配全图、回中四个按钮；边界用禁用态表达，不移除整组控件。
- `AgentControls.vue`：虚拟按钮须显式 `showControls` 才显示，AI 状态 DOM 保留。`layout.ts` 新增按指针能力判断触控键的纯函数，供 App 使用。
- `Sidebar.vue`：高度服从父容器并允许侧栏整体滚动；日志保留最小高度且自身可滚，长消息可换行。增加可点击“键位帮助（?）”和移动、背包、探索、右键查看的短提示，复用原 help 命令。
- `Settings.ts` / `assets/main.css`：新增持久化 `uiScale`（0.8–1.5，默认 1），通过根字体大小调整 rem 文本与间距，独立于地图 TILE_SIZE、游戏状态和录像。默认值不增加旧本地存储对象字段，保留 P2-6 旧设置守卫。

主线程已在 `App.vue` / `MainMenu.vue` / `zh_CN.json` 接入：全尺寸地图缩放控件、细指针紧凑窗口隐藏 DPad 但保留命令栏、界面大小选择，以及 `mobile.fit_map`、`ux1.help`、`ux1.key_hint` 翻译。
