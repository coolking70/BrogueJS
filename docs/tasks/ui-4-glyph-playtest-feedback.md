# UI-4：刻符界面试玩反馈整改

> 分支：`fix/glyph-ui-feedback`（工作区 `BrogueJS-newtheme`，基于 main `b0860eb`）。
> 来源：用户在公开试玩页（PC 端）试玩后反馈；问题 1 已由 Claude 在 1280×800 浏览器复现并定位。

## 待办

### 1. "更多"按钮点击后看不到扩展命令（bug）
- 现象：PC 端（1280×800，刻符默认布局）点击命令栏右下角"更多"，按钮文字变为"收起"，但扩展命令面板不可见。
- 已定位：`.command-overflow` 已渲染（6 个子项，`position: absolute`，`z-index: 70`，`display: grid`），但实测 `getBoundingClientRect()` 为 `top: -148, bottom: -8, left: 990, width: 290`——被定位到视口上方之外。命令栏本身在 `top: 754`（`.command-bar` 的 `overflow: visible`）。说明它的定位参照不是命令栏（某个祖先的定位上下文或 `bottom: calc(100% + …)` 规则在刻符布局下指向了错误的包含块）。
- 要求：扩展面板紧贴"更多"按钮上方弹出，完整在视口内；桌面、平板、手机竖屏/横屏、沉浸模式都要正确；Escape 与点击外部关闭行为保持。

### 2. 日志下方的信息行时隐时现，导致下方画面抖动（bug）
- 现象：日志区下面那一行（位置描述行 / flavor 行，`ThemeLog.vue` 的 `.tl-flavor`）时有时无，出现和消失时下面的地图跟着上下跳。
- 要求：该行**始终占据固定高度**（无文字时留空占位，不用 `v-if` / `display:none` 改变布局高度）；日志区整体高度固定，消息条数变化也不改变地图区域位置。检查沉浸模式单行消息同样不抖。

### 3. 左侧"面板"按钮用途不明
- 现象：刻符桌面布局左侧栏中部有一个"面板"按钮，用户不清楚其作用。
- 要求：先查明它在各布局下实际做什么（报告中说明）。刻符桌面布局下左侧栏已常驻显示状态与周围实体时，若该按钮冗余则移除；在确有用途的布局（紧凑视口打开抽屉、沉浸模式临时展开）保留，并让按钮文字或提示准确描述其作用（文本走 i18n）。

### 4. 点击日志展开完整日志（新功能）
- 要求：点击日志区（那几行消息的任意位置，而不只是小箭头）打开完整消息日志；完整日志有**可见滚动条**，支持鼠标滚轮、拖动滚动条、触屏拖动滚动；打开时默认滚动到最新消息；Escape / 点击外部 / 关闭按钮可关闭。优先复用现有的 `MessageJournal.vue`（App 里的 `journalOpen`），在其基础上补齐滚动条与拖动体验，不另起一套。
- 打开日志不得消耗回合、不得改变游戏状态、不进录像。

### 5. 点击周围实体查看详情（新功能）
- 要求：左侧"周围实体"列表（`ThemeNearby.vue`）中每一项可点击，打开该实体（怪物 / 物品 / 地形特征如楼梯）的详细信息，**复用现有的查看/检视功能**（DetailPanel、悬停描述或 CE 式 inspect 路径——先查清楚项目现有"查看"是怎么实现的、是否经过命令边界，报告中说明）。
- 若现有检视走 `game.executeCommand`（录像边界），就同样经 `ui/commands.dispatch` 发出；若是纯显示模型，就直接调用显示模型。**不得在组件里直接改引擎状态**，不得消耗实质随机流，不得消耗回合。
- 键盘可达：列表项可聚焦，Enter 打开详情；关闭后焦点回到列表。
- 沉浸模式展开面板里的周围实体列表同样可点击。
