## 3. 实施单元与完成标准

### UX-1A：死亡结算可操作性（优先）

先构造实际浏览器失败场景：启用动画、玩家低 HP、麻痹、相邻敌人近战致死；对照普通死亡、麻痹中毒死亡、麻痹气体持续施加。现有 `x3_u8a_forced_turns.test.ts:88-95` 只覆盖引擎麻痹中毒死亡，不能代替触屏结算验收。

观测 `isGameOver/isAdvancing/isInputLocked/lastAdvancementError`、待确认消息、按钮边界和实际命中元素；分别验证 MORE 确认、滚动、返回标题、重开。覆盖手机竖横屏、长背包、多条高分榜。结算组件已有移动端样式（`GameEndOverlay.vue:305-323`），不能只看基础 CSS 就宣称不支持移动端。

按复现结果修复：

- 明确消息确认与结算的展示顺序，确保所有确认与结束操作可点击、可滚动；不能用无条件清空消息队列掩盖问题。
- 若卡在推进中，修复相应收尾/异常路径，确保一次死亡、一次回合收尾、最终录像检查点完成后可保存。
- 麻痹长任务与永久不能操作分别记录。CE `Time.c:2841-2845` 有麻痹间 `pauseAnimation(25)`；Web `TimeCoordinator.ts:467-480`、`Game.ts:8725-8729` 同步耗尽强制回合。若测量证明需让帧，保留一条用户命令涵盖整段强制回合的合同，直至结束才提交 checkpoint；不得额外消耗回合或重复记录。

主要范围：`GameEndOverlay.vue`、`MessageAcknowledgment.vue`、`App.vue`、`ui/messageAcknowledgment.ts`；只有复现指向引擎时才动 `Game.ts`、`TimeCoordinator.ts`、`Logger.ts`。

完成标准：受控场景可经真实触摸事件完成确认、查看结算、保存录像、返回和重开；无残留遮罩、重复结算、控制台异常；同步/动画两路径最终状态与双流一致。

### UX-1B：背包优先处理物品字母

建立清楚的输入优先级：消息确认/文字输入 → 当前浮层及其子状态 → 游戏全局快捷键。不要只拦 d，也不要用事件监听注册先后来碰运气。

- 普通背包列表内按物品字母，与鼠标点该行进入同一个详情/操作菜单；选中物品本身不耗回合。
- 鉴定、附魔、使用、丢弃、装备替换等选物模式内，字母选择该模式的合法目标；缺失或不合格字母不落到全局移动/丢弃/探索。
- 详情菜单中的动作按键只作用于当前物品；关闭、取消、目标确认保持既有语义。输入名称时字母留给文本框。
- 改状态仍经 `executeItemCommand/executeCommand`；鼠标与键盘共用实际物品操作处理器，避免重复派发。

CE 依据：`Items.c:3597-3598` 绑定物品字母，`:3746-3784` 先选物品再显示详情；`IO.c:2546-2556` 的 d 属于主游戏命令入口。

主要范围：`Input.ts`、`InventoryOverlay.vue`，必要时抽取小型 UI 输入辅助模块；尽量不改引擎命令语义。

完成标准：背包内 d/a/e/i/h/j/k/l 等冲突字母都选择物品，背包外仍执行原键位；真实 DOM 事件不穿透、不开重复菜单、不移动玩家；执行后录像可独立回放、零 OOS。

### UX-1C：桌面交互、缩放、布局与提示

1. 地图悬停增加清晰的格子描边/淡底反馈，指向信息与侧栏同步；离开地图、打开遮挡浮层或切换目标模式时正确清理。只使用玩家已知信息，不暴露未探索内容。CE `IO.c:655-702` 是光标模式高亮的参考，不把它误称为被动 mousemove 的原样规则。
2. 全尺寸显示地图缩放入口，支持放大、缩小、适配全图、回中。默认桌面 zoom=1 保留既有等比/拉伸布局；主动放大才进入可平移跟随镜头。鼠标拖拽平移后不误发移动命令，坐标命中始终使用同一逆变换。
3. 滚轮缩放仅作用地图区域；保留 Ctrl/Cmd 浏览器缩放，侧栏滚轮仍滚日志。触屏保留捏合、拖动、点击与长按。达到缩放边界时控件不能一起消失导致无法放大回来。
4. “界面大小”与“地图缩放”分开：先保证浏览器 100/125/150/200% 缩放下功能完整，再提供基于字体/间距变量的界面大小设置（默认 100%，初始考虑 80–150%）。不对整个网页套 transform，不把 UI 设置写入游戏存档或录像。
5. 普通 PC 默认隐藏 AgentControls 可点击按钮，保留必要的调试状态读取；触控键显示由指针能力及显式偏好决定，不只看窗口是否紧凑。桌面浏览器放大后也不能突然出现虚拟方向键。紧凑布局仍须保有菜单、帮助和背包入口。
6. 侧栏及日志遵守父容器可用高度、设置正确的 flex 最小尺寸；空间不足时采用可用的滚动布局，保证最后一条日志完整可达。多怪物、多状态、长文字与短窗口一起验收。
7. 桌面提供可点击的“键位帮助（?）”，并以简短提示展示移动、i 背包、x 探索和右键查看；完整清单复用帮助页，避免另造一套不同的键位表。按钮、列表行、不可用动作补充一致的 hover/按下/禁用反馈。

主要范围：`App.vue`、`GameCanvas.vue`、`Sidebar.vue`、`AgentControls.vue`、`MapZoomControls.vue`、`MainMenu.vue`、`ReferenceOverlay.vue`、`ui/layout.ts`、`ui/mapCamera.ts`、`Settings.ts`、样式与翻译。

完成标准：1440×900、1280×720、1024×768、1280×560、390×844、844×390 及浏览器/UI 缩放组合可用；旋转不重建游戏；缩放后 hover、点击行走、投掷/法杖目标命中正确；显示操作不改变回合、事件日志和任何游戏 RNG 状态。

### UX-1D：自动记录、按需保存、结束可导出

恢复用户明确要求的产品语义：新局起自动记录在内存，无需开关；游戏中途和死亡/胜利结算时都能点“保存录像”，保存后可导出 JSON。首次点击保存前，不自动写入录像库；显式保存游戏时日志随快照持久化，是读档续录所需的存档数据。

- 复用现有 `executeCommand` 记录机制；不增设“开始录制”。结算页直接接入保存与导出入口，共用 App 处理器，保存结果在当前可见面板中反馈。
- 结算后返回标题仍保留本局可保存的内存记录，直到新局/载入另一局明确替换；保存能力不再仅由 `gameStarted` 控制。
- 动画/强制回合尚未完成时，保存请求等最终 checkpoint 落定后再执行，清楚显示等待状态；不导出半条命令，也不靠取消剩余模拟完成保存。
- 读档继续录制要验证“从开局完整记录”的来源。旧实现允许读档后继续世界推进却不追加日志，故不能简单把 `recordingFromNewGame=false` 改成 true。
- 首选在新快照 run 中保存明确的录制来源/连续性状态；新局创建，所有中断/载入/回放路径明确维护。缺失或为 false 的旧/合成快照不被冒充为完整录像；不做旧存档迁移。是否必须升存档 schema，由实现时字段契约与验证结果决定，录像格式不无故升级。
- 载入时检查事件索引连续、事件数与索引一致、末 checkpoint 与当前 tick/turn/depth/position/RNG/end 一致；空日志单独校验开局条件。来源标志和末 checkpoint 只是生产信任边界，不能声称足以证明完整世界；新增测试从种子独立重放至存点、续跑后对比世界快照，才是有效的端到端证据。
- 保存失败（配额/存储禁用）保留内存和既有已存录像，给出本地化原因及可用的 JSON 导出途径。导入、载入和保存语义分别明确，禁止后台自动覆盖用户已保存录像。

主要范围：`App.vue`、`MainMenu.vue`、`GameEndOverlay.vue`、`Game.ts`、`WholeRunSnapshot.ts`、U03 契约与录像存储辅助模块（必要时）。不无依据迁移录像库实现。

历史裁决：`docs/archive/dev-history/tasks/u-27.prompt.md:20` 当时允许“读档后续录或明确拒绝”；`reports/u-27.report.md:14` 选择了拒绝，并非 CE 强制。本轮用户要求补齐该能力。旧 `u_27_recording.test.ts:40-46` 的“残缺录像仍拒绝”断言应保留；若生产修改使旧前提失效，先反事实证明，再将前提换为无有效来源的残缺快照，另加新快照正常续录用例，不直接翻转断言。

## 4. 执行与验收安排

建议顺序：既有门禁收尾 → A 的复现与必要修复 → B → C → D → E 的测量和优化 → 汇总门禁/浏览器验收。E 可先做只读测量，再与 A 共用调度修复。共享 `App.vue/GameCanvas.vue/Game.ts` 的改动串行集成，避免多个执行者互相覆盖。
