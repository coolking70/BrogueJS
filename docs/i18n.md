# 文本与本地化

界面语言目前只有中文（`zh_CN`），使用 i18next。

## 1. 文件

| 文件 | 命名空间 | 内容 |
|---|---|---|
| `src/locales/zh_CN.json` | `translation`（默认） | 界面、消息、物品/怪物名称、状态文案等，扁平键（如 `move.path_blocked`、`status.player.haste_off`） |
| `src/locales/zh_CN.content.json` | `content` | 世界内容目录：地形描述与风味（`terrain.<CE_ID>.description/flavor`）、怪物专属召唤句与吸收状态词、DF 警报 |
| `src/locales/zh_CN.legacy.json` | （不加载） | 已退役键的归档；不被运行时读取，保留译法供参考 |

初始化在 `src/i18n.ts`。

## 2. 规则

- **所有玩家可见文本走 i18n**，组件模板和 logger 调用里不写硬编码中文/英文句子。
- `i18next.t(key, { defaultValue })` 的 `defaultValue` 写 **CE 英文原文**（不要写中文）：它是缺键时的兜底，也方便对照 CE。
- 文字优先复用 CE 汉化已有译法，与 CE 语义一致；不要为了通顺改变规则含义。
- 删除或停用某个键时，把它移到 `zh_CN.legacy.json`，不要直接删（`p1_30` 会检查）。

## 3. 守卫

| 测试 | 检查 |
|---|---|
| `p1_30_i18n_gate` | 扫描 `src/` 所有 `t()` / `$t()` 调用，键必须存在；数据驱动的 `name.*` 键全覆盖；变异名拼接不得含英文或多余空格；实跑若干回合不得命中缺失键 |
| `u24_hardcoded_text` | 组件与引擎中不得出现硬编码玩家可见文本 |
| `x4_r5_content_text` | 每种地形都有非空中文描述；CE 非空风味全覆盖；秘密地形未发现时返回伪装描述 |

注意：多数测试用空资源初始化 i18next（便于断言英文默认值）。需要断言中文结果的测试要显式 `import '../i18n'`（曾有测试只因默认值恰好是中文才通过）。

## 4. 新增文本的步骤

1. 在代码里用 `t('域.名', { defaultValue: 'CE English text' })`。
2. 在 `zh_CN.json`（或 content 命名空间的 `zh_CN.content.json`）加中文。
3. 跑 `p1_30_i18n_gate`、`u24_hardcoded_text`。
