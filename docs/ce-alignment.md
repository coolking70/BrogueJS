# 与 Brogue CE 的对齐

## 1. 原则

- **CE 源码就是规格。** 规则、交互、内容都以 CE C 源码的执行路径为准；web 代码旁的 CE 行号注释只是索引。
- **对齐的是"规则可观察结果"。** 同样的操作在同样的局面下，应当产生 CE 同样的效果与提示；不要求逐骰一致。
- **CE 的未定义行为不复制**（例如无合法落点时的越界访问），改为有限的失败策略。

## 4. 与 CE 的明确差异

- **录像**：web 命令日志 JSON（v2），不兼容 CE `.broguerec`；旧版本录像直接拒绝。
- **存档**：整局 JSON 快照，不做旧版迁移。
- **随机**：规则一致但同种子地图与 CE 不同；光照等显示随机使用独立装饰流。
- **web 自创内容**只保留定义，不进入正常生成（11 个自创蓝图、部分自创物品/符文）。
- **有意不激活的 CE 项**：冰、旧法杖洞、调试 DF、CE 停用的蓝图 48、仅 Bullet 变体的 CE72 等（缺位账本：`src/engine/Map/WorldCatalogAudit.ts`）。
- **界面**：网页/触屏交互（单击即走、长按检视、底部命令栏）是网页化适配，规则语义保持 CE。
- **战斗数值显示**：可选开关（默认关闭），不影响规则与录像。

## 5. 核对 CE 的方法

- 在 `.ce-reference/BrogueCE-master/src/brogue/` 中按函数名查找（`Movement.c`、`Items.c`、`Time.c`、`Combat.c`、`Monsters.c`、`Architect.c`、`IO.c`、`Globals.c`；变体数据在 `src/variants/GlobalsBrogue.c`）。
- 结论要读执行路径（条件分支、调用顺序），不要只读注释或函数名。
- 官方最新 CE：`npm run ce:fetch -- --source upstream`，或直接看 GitHub `tmewett/BrogueCE`。
